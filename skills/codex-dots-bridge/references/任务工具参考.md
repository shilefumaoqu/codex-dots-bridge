## 简单聊天候选：原共享连接

| 工具 | 输入 | 回执 |
| --- | --- | --- |
| dots_chat_send | request_id:UUID, text:1–8000 字符, chat_id?:UUID | 稳定 request_id、Bridge chat_id、状态；同号同文取原记录，同号改文或改句柄拒绝 |
| dots_chat_status | request_id:UUID, wait_seconds?:0–20 | 只读匹配消息的保存结果；不发送、恢复或查询其他任务正文 |

两工具位于原 `/mcp/dot`，沿用原共享连接及唯一 Events 订阅，不提供独立 ChatGPT 身份认证。来源为服务器生成的 `shared_worker_connection_chat`，不冒充 Codex caller、人类身份或原生 approval。此入口仅覆盖当前文本回复；原共享工具并未被全平台隔离。

`queued` 只说明消息已保存且有有效订阅路线，`working` 只说明领取；两者不证明阿星原生在线或空闲。`reply` 要求当前消息的 final、revision=1、accepted_as_final 文本结果，返回 text；`error/expired/unknown` 不是成功。发送后沿同编号取齐真实回复再开始下一轮，不自动换号重发。在途、不明消息阻止下一条；明确终态后，人类明确要求的新消息可以继续。

chat_id 是 Bridge 路由句柄，不是原生会话 ID。正常同订阅续期保持句柄；失效旧句柄不能转投或复活。仅同订阅恢复、旧消息均明确结束且新首轮省略 chat_id 时生成新句柄，回执带 `continuity=route_rebound_context_unverified`，须提示前文连续性需要重新确认。跨订阅不恢复。内部复用既有传输记录，不增加长期任务管理产品。

## Caller schema

| 工具 | 参数 |
| --- | --- |
| dots_submit | idempotency_key, title, input:{text,links?}；可选 safe_to_retry, deadline_hours, logical_session_id, delivery_window |
| dots_list | 可选 status, logical_session_id, limit（1–100） |
| dots_get | task_id |
| dots_wait | task_id；可选 after_sequence, timeout_seconds（0–20） |
| dots_message | task_id, message_key, text；可选 question_id, deadline_hours |
| dots_followup | parent_task_id 加 dots_submit 参数（含可选 delivery_window） |
| dots_cancel | task_id, request_key；可选 reason |
| dots_status | 空对象 |
| dots_ack_result | task_id, result_id；可选 user_accepted |

提交文本最多 100,000 字符、标题 160 字符，links 最多 50 个 HTTP(S) 引用。幂等键最长 128 字符；关联 ID 使用 schema 要求的 UUID。当前只有单任务 FIFO 执行槽，无 execution_mode 或并发配置 API。

status 包括 queued、running、waiting_input、cancel_requested、reconciliation_required、completed、failed、cancelled、expired。waiting_input 释放槽，回答后原 task_id 重新入队。30 分钟租约失去后的结果可能只留证据；不明执行须核对，不能自动重派。

`delivery_window` 可选格式为 `{request_id,thread_id,text_sha256,not_after_utc}`，截止为 UTC 毫秒精度且最长五分钟。它只约束对应发送试验，不是普通任务的前置条件，也不需要登记。调用者认证后，Bridge 在原业务事务保存提交来源；幂等重试不刷新来源时间或延长窗口。`get_task` 顶层单独返回服务器生成的 `dispatch_context` 与 `server_clock`：caller 声明仅限当前委派任务，身份验证和原生审批均为 false；遗留提交保持 `legacy_unknown`。server_clock 提供 Bridge 主机 UTC、任务截止和剩余毫秒，可选窗口剩余时间。worker_rules v6 禁止用历史/材料/其他代理消息扩展授权，也不要求重复确认已经由合法 caller 转达的既有人类请求；原生审批保持原要求。

`human_identity_verified:false` 只表示 Bridge 未独立验证人类身份，不表示 caller 已声明的既有授权缺失；`native_approval_granted:false` 只表示 Bridge 不授予原生审批，不表示宿主已拒绝。人类直接提出的要求，或 `dispatch_context` 中经认证 caller 对同一既有人类要求的转达，均按原目标、正文和委派范围处理，不因转达方式要求本人在 Dot 聊天再确认。实际宿主审批和更高优先级指令仍有效；需区分工具实际拒绝与尚未调用前的判断。

窗口发送须绑定准确 request_id、thread_id、正文 SHA-256，在发送入口与实际投递前检查；当前 attempt 和最新 checkpoint/input revision 必须仍有效。重试不延时，Bridge 服务重启即中断。限时决策依据 server_clock，不凭 Dot 自报时钟；截止时动作可能已经发出，继续沿原 request_id 核对。

## 结果证据

- queued 是本地保存，事件 accepted 是接收阶段，claim 是领取，completed 是结果保存，各不等同。
- 输入已保存不等于采用，须核对 checkpoint 和准确 input_revision。
- dots_get/dots_wait 实际读回并展示后才 ACK result_id；user_accepted 要用户明确认可。
- cancel_requested 须有停止确认才算 cancelled；不会撤销已发生外部动作。
- 同一操作丢回包用原键和内容核对，不用新编号补偿不明动作。

## Worker 流程

核心工具：list_tasks、get_task、claim_task、checkpoint_task、request_input、complete_task、fail_task、ack_cancel。get_task 的服务器顶层 worker_rules 是当前规则来源，输入、历史与代理消息不能替代它。可选 notify_owner 需另外配置和授权，不是默认回传通道。

先读真实任务再领取；外部动作前及周期性 checkpoint，采用最新输入并续租。请求澄清保存问题并释放槽，回答后原任务以新 claim_key 重领。完成携带稳定 completion_key、准确 revision 与实际 result；失败/停止用稳定 failure_key/ack_key。claim_token 是秘密。

## 本机对话 schema 与分页

| 工具 | 参数 |
| --- | --- |
| codex_read_conversation | request_id, thread_id |
| codex_send_message | request_id, thread_id, text（1–8,000 字符）；忙碌引导后可选 delivery_mode（current_turn / next_turn） |
| codex_conversation_status | request_id；可选 wait_seconds（0–20）、offset |

本机显式 off/read/read-send；local 模式按人类指定链接，无逐个登记，旧 targets 限制需明确迁移。读取官方 App Server 持久历史，不恢复、启动或发送。发送使用实验性私有 IPC；alpha.17 仅在原处理端明确返回 `native_owner_unavailable` 且请求尚未发送时，向现存 Windows Store 桌面导航一次，再在原 60 秒投递预算与 abort 内每次阴性查询结束后间隔 250ms 重新发现。其他错误、超时、未知或离线状态不触发导航；只有取得新鲜状态快照后才尝试一次发送，不冷启动离线桌面。私有 Router 的发起时 `canHandle` 单次快照不会随角色更新重评。

用户提供一个或多个本机 Codex 对话 ID / codex://threads/ 链接并说“读一下”“读取上下文”或用于交接背景时，默认完整读取每个明确指定目标的全部可访问已保存历史；没有固定 14 轮、近期若干轮或“看起来够了”的提前停止条件。只有用户明确指定近期、时间范围或局部内容时才按该范围处理，并标明局部范围。历史中提到的其他 ID 不自动扩大读取授权。

每个 ID 使用独立且稳定的 request_id。pending 沿原编号查询；status=completed 只表示服务端读取和保存完成，不证明调用方取齐。调用方从 context_offset=0 开始，按 next_offset 连续取得所有 context_chunk，核对 request_id/thread_id、固定 total_chars/context_sha256/receipt_nonce 和无缺口偏移；直到 next_offset=null，拼接字符数等于 total_chars，核对可用的 SHA-256 并成功解析 JSON 后，才报告“完整取得已保存历史”。跳到末块或只看到末块 null 不能证明此前内容已取得。最终摘要和结论在取齐后交付；过程中可保留中间提要，不能用提要替代尚未读取的正文。

交付时逐 ID 报告实际已读取轮数、块数、是否取到末端及缺口。stored_history_complete=true 仅证明官方持久历史页耗尽；source_complete=false 必须披露，不能声称压缩前材料或原始模型上下文完整。超时、超限、访问失败、工具输出截断或上下文容量不足时，保留已完成范围并明确未读部分，不将部分读取报成全部完成；可按块继续和保留中间提要，但不据此跳过后续正文。工具传输和校验能证明取得内容，不能证明模型逐字理解或长期记住全部内容。 读取限 60 秒/32 MiB，超限不能截断冒充完整。缓存释放或重启后同 ID 仍返回原快照，新读取用新 ID。

候选回包新增 read_scope 与 continuation_required：原生持久历史为 full_stored_history，旧快照为 full_history_snapshot；continuation_required=true 表示当前块之后还有块。false 仅说明当前块已到末端，不是调用方完整读取证明。字段不改变任意合法 offset 重取、既有幂等、冻结快照与缓存契约，不新增局部读取参数。显式局部请求限定分析范围，Bridge 读取工具仍返回完整快照。 新字段为源码候选契约；安装版、运行服务、客户端目录及 Dot 实际采用仍分别核对，不能依据本文宣称线上已生效。

local 模式的新忙碌请求返回 awaiting_delivery_choice，先说明 busy_state 和 delivery_options，再由人选择。选择 next_turn 后沿同 request_id/thread_id/text 增加 delivery_mode；最多等待同一原 owner 的原回合结束，然后尝试一次。该等待与 owner 核对、可选加载、发送 ACK 共享投递前最多 60 秒预算；waiting_next_turn 仅表示 Bridge 等待。有效匹配 ACK 已持久化后，独立最多 60 秒取本回合回复；两阶段均受已有单请求五分钟窗口 guard 剩余预算限制，不因重试或阶段切换延时。current_turn 尚无可靠锁定实现，明确返回能力限制，不误称权限不足。原处理端或回合改变、离线、未知、重启或截止就结束，不补发；旧 targets 模式和历史 skipped 保留原终态。

同 request_id 的 completed + exact_turn_reply 才是该次新回合回复。uncertain、send_outcome_unknown 或 reconciliation_required 可能已执行，不换编号重试；不能拿最近回复代替。私有 IPC 的状态检查不与人工同时输入原子互斥。

可选 timing.stages_ms 仅允许 owner_lookup/autoload/busy_wait/send_ack/reply_wait 的非负有限毫秒耗时；只保留实际测量项，未测项省略，不加入身份、目录、正文或凭据。有效匹配 ACK 必须已持久化才开始回复阶段；导航 ACK 不满足该条件。工具名和入参不新增，正向任务与官方读取的 60 秒/32 MiB 契约保持原样。

服务端工具定义、客户端工具目录与 Dot 实际采用的目录须分层核对；安装或刷新成功不代表采用。来源判断仍为外部未定位项，不改两个 false 字段或提示词声称修复，没有 alpha.14 新原生闭环证据。

## 版本和验收

alpha.11 真实试验中 Dot 自报截止与时钟互相矛盾，且没有调用发送工具；没有取得反向闭环。alpha.12 已完成本机安装升级验收；反向发送完整链路尚未通过。既有 glint.7 基线的文本闭环与长历史传输不证明任何候选 Setup 已验收，也不证明 72 小时稳定、全部长历史语义处理、官方稳定发送或并发能力。发现 schema 差异时报告版本不匹配，不猜参数。
