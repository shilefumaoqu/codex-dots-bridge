# 发布门禁

当前候选按完整验收门槛发布：各真实链路至少 30 次往返、Events 领取、客户端实际采用、Windows 资源预算和 72 小时稳定性分别核对。源码、ZIP、Setup 与原始实测按提交和摘要绑定；新 Setup 需要本批安装证明。缺失、失败、未知或中断不能记录为通过，`-RequireEvidence` 不放宽。

下面的 alpha.21 有限验证发布决定仅属于历史版本，不构成当前候选跳过完整门槛的授权。

alpha.21 按明确的发布决定作为有限验证的预发布版本分发。最终包安装验收、专门审查及生产部署已完成；正向合成任务和用户直接发起的反向单样本已有真实通过证据。自然 Events 及时领取、先前宿主目录拒绝根因及其他未验证场景分别保留；不能把本次发布或单样本写成全部门禁通过。最新状态见[alpha.21 启动恢复验收](alpha21启动恢复验收.md)。

本页是当前候选版本发布必须执行的检查列表，不是通过报告。逐项以当批实际证据记录完成、失败、跳过或未验证；具体结果以该版本 Release 验收记录为准，不能从静态包文档推断检查通过。

**历史 alpha.21 发布决定：**在已说明真实忙碌、原生异常及长期运行验收缺口后，用户明确要求发布当前 alpha.21。此次按该决定提供试用版本，并在 README、Release 与验收报告披露缺口。原严格门禁评估仍为未全部满足，`-RequireEvidence` 校验器和真实/隔离分类不作改动；不制造全部通过的证据。成品哈希、来源与许可、公开文件隐私、安装生命周期以及已记录的真实往返仍按最终产物核对。

## alpha.21 当时的证据缺口

alpha.21 已核实正向合成任务与用户直接发起的一条反向往返成功。新版 local 忙碌选择、选择下一回合及等待中断仍缺真实桌面样本；busy、offline、错 owner 和回执/回复超时的部分通过项来自注入 transport 或 FakeSocket，须保留隔离测试归属。真实 HTTP/stdio 的重复请求、等待超时、服务停止及错误问题/结果关联验证只证明相应桥接层行为，不能替代上述原生桌面场景。当前不填全部 `basicErrors` 为真实通过，不修改校验标准以发布；此前宿主目录拒绝根因与自然 Events 及时领取也仍未闭环。

- alpha.17 已完成的检查：31 项 transport 中 28 项通过、3 项旧平台项跳过；环回可访问环境下 54 项协议/正向相关 regression 全部通过；typecheck 通过。构建及同一实际 Setup 的新装/重复安装/保留数据卸载 13 项、旧版升级 14 项通过。
- Codex 专门代码审查未发现可操作问题；指定 `gpt-6.1-sol / high`，实际运行模型未独立核验。
- 新 CLI 合成空对话只读对照：一次导航；首轮 10.14 秒 no-client，桌面 role/success 日志出现在首轮查询中间，第二轮新查询 2.334 毫秒发现 owner。私有 Router 只在发起时读取一次 `canHandle`，不随角色更新重评。该对照没有发送聊天。后续独立真实样本的 Dot 往返已通过，不能把两项证据混为同一次试验。
- alpha.17 安装、实际载荷、新 caller 握手、Setup SHA256 与新 Dot 发送/回传已核对；记录见本版本验收页。正式 commit/Release 资产绑定与下载验证尚未执行，不借用旧版证据。最终验收文档写于冻结安装包之后，保留原包字节，后续发布须附带最新报告。
- Setup 复用同批已校验 ZIP 载荷；校验构建出的 EXE、SHA256 与版本，不发布开发工作区原始材料。
- 最终 `check-package.ps1 -RequireEvidence` 必须传入 `-SetupExe` 实际安装器，同时绑定 `-SourceCommit`、`-SourceZip`、`-WindowsZip`、`-ReleaseNotes` 与私有 `-Evidence`。alpha.7 缺 Setup 即失败；后续需 Setup 的版本可显式加 `-RequireSetup`。旧版无 Setup 的 ZIP 验证兼容保留，任何版本提供 Setup 后都必须验证其摘要与安装证据。
- 证据 schema 为 1、`mode: real`，新增顶层 `setupSha256`；`installUpgradeUninstall` 需 `status: passed`、`mode: real`、同一 `setupSha256`、实际 `fromVersion`、本版本 `toVersion`，以及 `installed`、`upgraded`、`uninstalled`、`uninstallPreservedData` 全为 true。升级必须从不同旧版本到本版本，同版重装不能替代。其 `evidence: {path, sha256}` 绑定私有原始实测记录；不将 schema 通过记为实测通过。
- 最终 Setup 重新编译或字节变化后须重新绑定对应实测证据；同版本号或相同载荷 ZIP 不能复用旧 EXE 的验收。安装、升级、卸载证明与云端普通任务证明分别记录，不互相替代。
- 隔离验收包含空格路径、干净安装、重复安装、升级、外来/修改过的注册冲突、启动/停止及卸载保留数据。用户不需要全局 Node/npm。
- 密钥和配置不完整保持 pending，安装不创建虚假成功记录；自身归属检查不得放宽以绕过失败。

## 真实链路验收

- 新包 Codex 实际发现当前 caller 工具目录并调用 dots_status，核对新版参数及实际采用。
- 使用者自己的私有插件、Dot 与 queue=tasks 订阅实际连接，文本派单、领取、结果读回及澄清沿原 task_id 继续。
- 可选本机读取按全部 next_offset 取齐，核对持久页完整标记并披露 source_complete=false。
- 可选发送在明确授权的空闲样本中关联同 request_id 的新回合 exact_turn_reply；新 local 忙碌样本返回状态与选择引导，未经人类选择不排队，next_turn 等待绑定原 owner 与原回合。离线、未知或等待条件失效就结束、不补发；发送不明不盲重试，历史 skipped 不重放。未加载目标、忙碌选择及等待中断的真实验收分别记录，模拟通过不替代。
- 升级后按原 ID 读取旧任务、结果与 ACK；卸载后保留独立数据。备份恢复单独记录，云端恢复不以本地测试代替。

- alpha12 caller 上下文与限时发送试验：核对 authenticated caller 来源仅在当前委派范围生效、legacy_unknown 不回填、重试不刷新原始时间；窗口按准确 request/target/text、当前 attempt 和最新 checkpoint/input revision 检查，重启后中断。发送入口和真实投递前均验证 Bridge server_clock 剩余时间；若动作可能已发出，按原 request_id 对账。隔离测试不替代真实反向调用。
- alpha11 的历史试验记录须保留其原始结果：Dot 自报时钟与截止矛盾且没有调用工具，因此未取得反向闭环，不标为通过。
- alpha.13 历史专项：worker_rules v6 与三个本机对话工具调用说明已部署；本机只读 `get_task` 确认版本及来源事实字段，尚未完成新的 Dot 真实任务或反向发送交互验收。说明澄清不保证能通过更高优先级宿主审批，也不能把 host-level 拒绝归因于文案。核对无新增权限/目标/接口，状态机、历史读取、IPC、时钟、核心流程和图标未变更。协议测试与审查、打包及安装生命周期已通过。alpha.12 已取消的授权窗口不得重跑，新的真实发送试验需新的明确授权。
- alpha.12 未加载目标只读 owner 探针约 10 秒未发现原生 owner，未发生自动加载或发送。既有已加载目标真实往返成功记录继续保留；alpha.17 未加载目标自动往返已有一条真实通过记录，忙碌续接仍需独立验收，须各自记录，不能从模拟测试推断通过。

既有 glint.7 的普通文本闭环与 667 块长记录传输是历史基线证据，不等于本次 Setup 或所有账号通过。不能声称全部 2100 万字符语义处理、72 小时稳定性、官方稳定发送或并发能力。
