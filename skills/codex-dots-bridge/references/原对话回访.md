# 桌面原对话回访

仅在用户明确要求启用时使用。它只负责让 Codex 回来查询和报告，不负责唤醒 Dot 执行任务，也不是外部消息回传；不启用仍可正常派单和主动取回。来源项目已有跟进机制时不重复创建。回访是 Codex 官方自动化能力，不是 Bridge 的内部计时器；用户可以不启用。它需要当前桌面环境提供可用的原对话自动化工具。

用官方工具创建附着当前对话的回访，并保存真实 automation ID。默认间隔 15 分钟，最长 24 小时；用户指定更短窗口或其他频率时从其要求，不因默认值延长已授权时间。工具不支持所需周期或停止能力时如实报告，保留人工查询方式，不能承诺已启动。CLI 工具缺少官方调度能力时不能以本机计划任务冒充。

回访提示词应包含：

> 按 Codex Dots Bridge task_id `实际任务ID` 查询同一任务，使用 $codex-dots-bridge。保持原任务身份，不重新提交。状态无变化或无可操作内容时保持安静。只在出现新的持久 question_id 或新的终态 result_id 时向本对话报告一次。问题展示原文和选项，等待真实用户回答，不代答。终态读取并展示实际结果后记录 codex_received；user_accepted 仅在用户明确认可后记录。终态、用户取消回访或到达实际截止时间时，通过官方工具停用此回访。连接故障如实报告一次，不能自动改账号、改部署或重派任务。

填写实际截止时间、task_id、去重标识和创建后返回的 automation ID。若当前环境的正式工具要求在提示词中配置通知渠道，遵循用户已授权范围；不因此额外发送消息到第三方。

创建被接口接受只证明已保存配置。首次实际回访、终态报告一次及终态停用必须各自核验；未实际发生时保留“未验证”。禁止私有 IPC、未公开 API、修改 Codex 历史文件或模拟用户输入来唤醒对话。
