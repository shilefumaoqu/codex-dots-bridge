# 发布与升级

当前 alpha 版本为 `0.2.0-alpha.21`，已完成最终包安装验收、专门审查和本机部署。正向合成任务与用户直接发起的一条反向往返均取得真实结果；自然 Events 及时领取及先前宿主目录拒绝根因仍未闭环，本次按明确发布决定提供有限验证 alpha，原门禁缺口保留。详见[alpha.21 启动恢复验收](alpha21启动恢复验收.md)。alpha.20 历史记录保留，其观察到的后台退出根因仍未知。

首次安装的 autostart 默认 unchecked，启用后在当前 Windows 用户登录时启动，不承诺登录前启动。升级保留已有 autostart setting；`run --stop` 仅停止当前服务。alpha.21 在核对同用户、实例归属、PID 创建时刻、状态及端点后处理已证实的同次开机陈旧锁和 PID 复用；身份或状态不明时保留现场，不结束无关进程。只停用已核实属于同一 Bridge 实例的旧登录入口，并保留回滚材料。alpha.19 原先仅处理旧 boot 完整双锁的规则与测试保留在其[历史验收](alpha19启动恢复验收.md)，不替代 alpha.21 的实现与证据。

## 来源与发布资产

源码仓库为 [shilefumaoqu/codex-dots-bridge](https://github.com/shilefumaoqu/codex-dots-bridge)，下载入口为 [GitHub Releases](https://github.com/shilefumaoqu/codex-dots-bridge/releases)。访问范围以仓库当前可见性为准；如仓库为私有，需登录有访问权限的账号。以该版本 Release 中实际列出的资产与记录为准。

使用者应在正式 Release 核对版本、Setup/ZIP 及 SHA256 文件，不使用猜测的资产地址。源码、桥接运行程序与分发包需版本一致；使用者自己的私有插件连接属于独立配置，不分发开发者身份与凭据。

## 构建与发布顺序

1. 按公开文档白名单检查源码、链接、版本、秘密格式、第三方来源与许可；需要公开历史时另做明确范围的历史检查。
2. 类型检查、构建、测试与适用的官方 Codex 安装覆盖；记录真实结果及跳过项，不将未运行远端 CI 写为通过。
3. `scripts/package.ps1 -IncludeTunnel` 生成含锁定运行时、生产依赖与官方 Tunnel 的校验载荷。
4. 用 `scripts/build-setup.ps1 -Compiler 官方InnoSetup编译器路径` 将同批载荷构建为 Setup；可用 `-PackageRoot` 指向已校验载荷、`-OutputDirectory` 指定新输出目录，实际参数以脚本 help 为准。构建结果与安装生命周期须分别验收，不从其他版本猜 Setup 参数。
5. 在独立隔离目录与数据目录验收 Setup 的安装、重复安装、升级、冲突保护、卸载保留数据；再实际确认 MCP/Skill 加载、连接与新包文本闭环。
6. 完成本批差异审查及[发布门禁](发布门禁.md)，记录历史证据、新包证据和仍未验证项。
7. 全部验收门禁完成后，核对目标仓库、可见性、commit、Tag、附件与 Prerelease 正文，再执行发布。alpha.21 本次按当前明确发布决定作为有限验证预发布分发，保留严格门禁缺口，不能由一条成功样本推定全部门禁完成。

构建复用锁定 ZIP 载荷与许可材料，保留 Node/Tunnel 伴随许可。CI 或构建成功不会自动发布；正式上传后再核对实际下载、校验、版本与链接。

alpha.20 还需分别验收托盘三行状态、鉴权失败/未知与版本不一致的 amber 提示、右键自启勾选及退出仅关闭界面。核对安装入口、后台服务、唯一 owned Startup VBS、开始菜单和同实例托盘均指向本批程序；开启/关闭自启不得改变当前服务运行，升级应保留关闭选择。隔离窗口渲染和单实例检查不替代真实安装或登录重启。

alpha.14 另核对投递前最多 60 秒、有效匹配 ACK 持久化后独立回复最多 60 秒及两阶段的原五分钟窗口剩余预算，确认不延长授权截止。可选 `timing.stages_ms` 仅发布五个白名单阶段的已测耗时；未测项省略，身份与业务原文留在受保护的验收材料中。工具名称、入参、正向任务与官方只读历史不新增或改变。

验收回填按 implemented、isolation、deployed、real-blocked 分层记录。部署后分别核对服务 `tools/list`、客户端实际工具目录与执行 Dot 的实际采用；安装完成、服务在线或刷新返回成功不代替后两层。未调用工具前的来源判断仍是外部未定位项，不改两个 false 字段或提示词宣称修复。私有真实样本的结果由当批验收负责人脱敏回填，不恢复旧已取消试验。

## 升级与回退

安装程序与用户数据分离，升级、卸载按保留任务、结果、配置及凭据的契约执行。具体版本和环境的真实验收结果以该版本 Release 记录为准。

1. 记录旧版本、安装位置和 data-dir；使用旧版 backup 创建受保护备份，保留旧安装材料。
2. 读取活跃任务；alpha.20 的 Prepare 在停机前遇到 queued、running、waiting_input、cancel_requested 或 reconciliation_required 即拒绝升级。任务状态未知时先核对原实例，不能按零任务继续。允许维护时再停止本实例并确认相关子进程退出。云端工作可能继续，未知任务不重派。
3. 用新版安装器升级程序，沿原 data-dir 更新本项目 owned 注册；核实并关闭同实例旧托盘，统一安装入口、服务、Startup 与开始菜单，保留自启开关。不覆盖外来同名或用户修改的内容，冲突须保留并报告。
4. 新对话实际发现工具，调用 status/doctor，读回旧 task_id/result_id、revision、ACK 与订阅，再做一条独立无副作用文本任务。
5. 回退先停新版，移除其 owned 注册并保留数据，再用旧安装材料重新注册。程序和注册回滚不还原数据库，不覆盖回退期间已变化的任务。未来数据库迁移可能影响降级，须按实际兼容说明或另行授权的离线备份恢复，不能盲目覆盖。

现有 ZIP 路径升级时先停止旧实例，旧 uninstall 移除本项目注册并保留数据，新 `scripts/install.ps1 -DataDir 原数据目录` 重建。若 Codex 原生路径变化，按当前 CLI help 显式指定自己的安装路径，不猜旧路径；归属冲突不自动删除。

## 离线恢复

恢复限定同账号与同 Dot。所有相关源/目标实例先停止，恢复到空目标；备份含密钥，应受当前用户/SYSTEM ACL 保护。恢复保留 active 订阅与待投递事件，启动前核对工作区、Dot 与 callback 归属。恢复命令成功不等于任务回读成功，云端切换需要独立验收。详见[维护与故障排查](维护与故障排查.md)。
