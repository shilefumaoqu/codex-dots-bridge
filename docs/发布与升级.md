# 发布与升级

当前源码候选：`0.2.0-alpha.4`。源码、运行程序和 Windows 包沿用该版本；部署者自己的 ChatGPT 私有插件包使用独立版本，不随开源源码分发。预发布不是 v1.0 稳定验收。

## 发布来源

公开仓库为 [shilefumaoqu/codex-dots-bridge](https://github.com/shilefumaoqu/codex-dots-bridge)，下载入口为 [GitHub Releases](https://github.com/shilefumaoqu/codex-dots-bridge/releases)。版本 Tag 与 Release 需维护者明确授权；源码通过发布分支和 PR 合入，远端 CI 成功后创建不可覆盖的版本。

1. 运行源码公开检查：`node scripts/check-release.mjs`；完整历史扫描另加 `--history`。
2. 类型检查、构建、测试并强制官方 CLI 安装覆盖；检查 npm audit 和第三方许可。
3. `scripts/package.ps1 -IncludeTunnel` 生成带版本和时间的 ZIP、同名 `.sha256`。重复构建保留旧包，不覆盖历史产物。
4. 解压候选包至含空格的隔离目录，运行包内 `scripts/check-package.ps1`；隔离数据和 CODEX_HOME 验证初始化、重复安装、启动/停机、查询、备份恢复、卸载保留数据。
5. 检查本批差异，并按项目规则完成专门 Codex review。记录指定模型、实际方式、测试边界及仍未验证项。
6. 源码快照和 Release 内容准备好后请求维护者确认具体公开仓库、commit、待发布Tag、附件与预发布状态。确认前不 push、不打 Tag、不创建 Release。
7. 确认后上传公开源码、等待远端 CI 成功，再创建不可覆盖的版本 Tag 和 **Prerelease**。上传 ZIP、SHA256 和源码；核对资产下载、校验、README链接及 Release 正文。安全私密报告入口由维护者启用。

GitHub CI 只构建并上传 Actions 验证产物，不自动打 Tag 或发布 Release。CI 未实际运行不能写为通过。npm 的 `private: true` 防止意外 npm 发布，不影响 GitHub 源码公开。

## 本次公开源码方式

公开源码从已检查的技术快照构建，不上传开发工作区的运行资料、秘密、原始日志或私人记录。历史与已发布附件的隐私处理须明确范围并保留受保护恢复材料；发现真实秘密仍须先撤销/轮换，不能仅修改文档。

## 升级与回退

1. 记录当前版本、安装位置及 data-dir，使用旧版 `backup` 保存受保护备份。备份包括凭据，不上传 GitHub。
2. 旧版执行 `run --stop`，确认 Bridge、Tunnel、guardian 和 supervisor 都停止。停止服务不代表 Dot 云任务已停止；运行中的旧任务仍须沿 task_id 核对。
3. 新包解压到独立固定目录。若换安装根目录或 Codex 原生 EXE 路径，用旧版 `uninstall` 移除本项目注册，保留任务数据；若桌面升级已删除旧CLI EXE，使用新版包内 `dist/main.js uninstall --data-dir 原data-dir --codex-command 新的原生codex.exe` 核对并移除原owned注册（仍拒绝外来或修改过的条目），再用新版 `install.ps1 -DataDir 原data-dir` 重建注册。用户修改过的或外来同名注册须人工核对，不能覆盖。
4. 新版沿原数据目录启动、诊断，在新 Codex 对话实际发现工具，读回原任务。该版本不变更数据库 schema，不自动迁移 P0 数据。
5. 需要回退时先停新版，用其卸载注册（保留数据），再用原安装目录重新注册；数据库已被未来版本迁移时须按该版本的兼容说明或使用离线备份恢复，不能盲目降级。

不要同时运行升级前后的实例，不以新建任务“恢复”未知外部操作。

## 备份恢复范围

仅面向同一账号、同一 Dot 的离线恢复。**所有原实例及目标实例必须先停止**；CLI检查目标停机，不自动保证备份源已停止。恢复保留实例身份、凭据、Tunnel、active订阅和待投递事件；启动可立即向旧 callback 投递，必须在启动前核对原工作区/订阅仍属于自己。不得用于不同账号/Dot迁移。云端生产恢复切换未完成真实验收，隔离SQLite与凭据恢复已验证；详细命令见[维护与故障排查](维护与故障排查.md)。
