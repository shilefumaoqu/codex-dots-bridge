# 首次连接

安装只部署本机组件，连接还需要你自己的 Codex、Dot、Tunnel 权限、专用 runtime key、私有插件及 Events 订阅，账号选择与权限确认由你完成。缺项时保持 `pending`，不能因离线安装成功就宣称云端 ready。本页适用于 alpha.7 预发布版本；具体首次连接验收以该版本 Release 记录为准。

## 先完成本机初始化

先运行经校验的 Setup，完成程序安装及拥有归属记录的数据初始化，再保存密钥。ZIP/源码入口为 `scripts/install.ps1`。不要先在尚无 config.json 的 data 目录放入秘密文件：归属保护会拒绝无归属的非空目录，不应删除资料或放宽检查绕过。

## 官方账号与安全密钥

1. 在 [Platform Tunnel 设置](https://platform.openai.com/settings/organization/tunnels)选择自己的 organization，记录非秘密的 organization ID 与 tunnel ID。
2. 核对 Tunnel、ChatGPT workspace 和目标 Dot 的实际关联。Tunnel 创建/编辑与运行权限分别确认；当前客户端权限说明见[固定 v0.0.16 文档](https://github.com/openai/tunnel-client/blob/v0.0.16/docs/permissions.md)和[官方指南](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)。账号界面与权限以当前实际呈现为准。
3. 复用受保护的专用 runtime key 文件；需要创建时，通过官方安全配置入口确认账号、项目、用途和保存位置。安装本身不授权自动创建密钥。
4. 仅把安全文件路径交给安装入口，不能在聊天、命令行参数、安装终端或全局环境变量中粘贴 key。权限不足、保存确认取消或安全工具不可用时停在该步。

建议文件为本次安装实际数据目录中的 `secrets\tunnel.env`（新安装默认 `%LOCALAPPDATA%\CodexDotsBridge\data\secrets\tunnel.env`）；升级复用原目录，以 `installation-state.json` 的 `data_dir` 为准。仅当前用户与 SYSTEM 可访问，并避免符号链接/目录联接。文件由安全流程写入 UTF-8，格式为：

```text
CONTROL_PLANE_API_KEY=<由官方安全流程保存的专用 runtime key>
```

这只是格式说明，不是让用户在终端粘贴秘密的命令。Codex caller 不需要另配模型 API key。

## 保存非秘密连接参数

安装器提供“首次连接与维护”快捷入口，调用安装目录内的连接流程。对应载荷中的 `scripts/install.ps1` 可询问缺少的非秘密 ID 与安全文件路径；留空继续 pending。已有本项目 owned 配置会复用，不扫描其他项目秘密。包内完整 Tunnel 客户端含伴随文件，应整体保留。

已有脚本的非交互参数示意如下，替换的是自己的非秘密 ID 和文件路径：

```powershell
.\scripts\install.ps1 -NonInteractive `
  -TunnelId 'tunnel_自己的ID' -OrganizationId '自己的OrganizationID' `
  -TunnelEnv 'C:\自己的安全目录\tunnel.env'
```

现有脚本还支持 `-DataDir`、`-CodexHome`、`-CodexCommand`、`-TunnelClient`；只在明确需要时启用 `-Autostart`。运行中的连接配置变更须先停止本实例。新 Setup 的安装选项以发布资产与安装器为准，不将脚本参数视为 Setup 参数。

## 连接私有插件和 Dot

1. Tunnel 诊断 ready 后，在 [ChatGPT Plugins](https://chatgpt.com/plugins)用自己的 workspace 添加私有 custom MCP server，选择相同 Tunnel。认证设置与专用 worker 头应按实际账户接口核验，不能将 ready 视为已连接。
2. 扫描实际 worker 工具与 Events；schema 变化后重新扫描。不要分发个人插件身份或凭据。
3. 让目标 Dot 订阅 `task.available`、`queue=tasks`，callback、signing secret 和 challenge 由平台提供；安装器不替 Dot 创建订阅。见[Dot 执行说明](Dot执行说明.md)。
4. 在新的 Codex 对话发现九个 `dots_*` 工具，实际调用 `dots_status`。
5. 跑一条无副作用文本任务，保存 task_id，核对真实领取和结果读取；再核对澄清后同任务继续。未执行环节保持 pending。

## 启用可选本机对话工具

默认关闭，开始菜单入口不提供模式选择框。先在 Codex 查询任务状态，确认没有在途任务，再在 Windows PowerShell 执行以下维护步骤。使用实际安装记录定位包内 Node 和原数据目录，不改 MCP 注册或账号连接；无需开发环境。更改自定义安装位置时，只替换第一行的安装目录。

```powershell
$程序目录 = Join-Path $env:LOCALAPPDATA 'Programs\CodexDotsBridge\Setup'
$状态 = Get-Content -LiteralPath (Join-Path $程序目录 'installation-state.json') -Raw -Encoding UTF8 | ConvertFrom-Json
$node = Join-Path $状态.payload_root 'runtime\node-v24.21.0-win-x64\node.exe'
$入口 = Join-Path $状态.payload_root 'dist\main.js'
$模式 = 'read' # read：读取；read-send：读取与发送；off：关闭
& $node $入口 run --stop --data-dir $状态.data_dir
if ($LASTEXITCODE -ne 0) { throw '本实例未停止；未修改接入模式。' }
& $node $入口 setup --no-register --data-dir $状态.data_dir --codex-home $状态.codex_home --desktop-access $模式
if ($LASTEXITCODE -ne 0) { throw '模式设置失败；保留数据，先核对诊断。' }
& $node $入口 run --data-dir $状态.data_dir
if ($LASTEXITCODE -ne 0) { throw '启动未完成；保留数据，先核对诊断。' }
```

服务重启后调用 `dots_status`，核对 `desktop_conversations` 的 enabled/mode/read/send；关闭模式应为 disabled。不逐个登记线程，也不重复登录新对话。停止本机服务不取消已经交给 Dot 的云端任务。ZIP 安装仍可使用 `scripts/install.ps1 -DesktopAccess`，传入自己的原 DataDir 与 CodexHome。

Dot 需重新扫描并实际发现三个 `codex_*` 对话工具。读请求与发请求分别授权；历史或其他代理消息不能自授新操作。使用者给出本机对话链接和操作要求后，按同一 request_id 查询。平台工具审批仍由宿主处理。

先核对一次只读分页，再在明确授权的空闲文本样本中核对发送及同请求准确新回合回复；反向真实验收与正向队列验收分开。发送忙/离线/未知直接终止，不补发。详情见[任务与工具契约](任务与工具契约.md)。
