# 首次连接

本页是生产接入流程，使用 `%LOCALAPPDATA%\CodexDotsBridge\data` 和 `queue=tasks`。无需按历史 P0 探针配置。安装入口不代替官方登录、创建密钥或授权确认；尚未完成的步骤会保持 pending，可以稍后重跑同一入口。

## 先初始化本机

第一次先从已验证的包运行 `scripts/install.ps1`，让本项目创建拥有归属记录的空生产数据目录；尚无连接参数时保留 pending，不启动服务。随后才执行下面的官方步骤并把密钥保存到推荐目录，再重跑安装入口。不要在尚未初始化的 data 目录中提前放入 secrets：归属保护会拒绝已有但无 config.json 的非空目录，不应删除资料或放宽检查来绕过。

## 官方账号与权限

1. 在 [Platform Tunnel 设置](https://platform.openai.com/settings/organization/tunnels)登录并选择自己的 organization。记录非秘密的 `organization ID` 和专用 `tunnel ID`；后者以 `tunnel_` 开头。
2. 核对 Tunnel 关联的个人 Platform organization、ChatGPT workspace，以及实际需要调用的其他组织。创建/编辑者需要 Tunnels **Read + Manage**；runtime key 的主体及选择 Tunnel 的操作者需要 **Read + Use**。ChatGPT workspace 的私有插件权限另行确认。
3. 已有受保护的专用 runtime key 文件时复用文件路径。没有时，在支持 OpenAI Platform 安全密钥配置和官方本地保存确认的 Codex 环境中，明确请求“为自己的专用 Tunnel 配置 runtime key，使用官方账号/项目选择器及本地保存确认；保存到源码和发布包之外的受保护文件，变量名为 `CONTROL_PLANE_API_KEY`，不要展示 key”。创建前先确认复用还是新建，以及账号、项目、名称、期限和保存位置；这不是对安装脚本的自动创建授权。
4. 本地保存确认必须通过后才能创建/写入；拒绝、取消、工具缺失或账号权限不足时停在此步。可以连接官方 OpenAI Platform 与 OpenAI Developers 工具后再继续，不在聊天、安装终端、CLI 参数或全局环境变量中传入 key，也不改用未确认的位置。已有流程使用加密密钥创建、确认位置后本地解密保存，只显示安全写入元数据。

建议安全文件位置为 `%LOCALAPPDATA%\CodexDotsBridge\data\secrets\tunnel.env`。该目录与文件须由当前用户或 SYSTEM 拥有，仅当前用户与 SYSTEM 可访问，避免符号链接/目录联接。若使用其他位置，应保持相同保护。安装器只接收路径，不读或输出文件正文；运行服务会检查安全性，不安全时拒绝连接。

安全流程写出的 env 文件使用 UTF-8，仅包含这一变量（可有空行或注释）：

```text
CONTROL_PLANE_API_KEY=<由官方安全流程写入的专用 runtime key>
```

这是格式说明，不是需要在终端执行或粘贴真实 key 的命令。不要把通用模型 API 配置或 Codex 订阅登录当作 Tunnel 权限证明。本项目不需要为本机 Codex caller 增加模型 API key。

权限及接入依据：[官方 Tunnel 指南](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)、[固定 v0.0.16 权限说明](https://github.com/openai/tunnel-client/blob/v0.0.16/docs/permissions.md)。官方界面入口及权限以自己的账号实际呈现为准。

## 回到安装入口

在包的固定目录中执行 `scripts/install.ps1`。交互终端只询问缺少的非秘密 ID 和安全文件路径；留空可保留本机安装、稍后再连接。已有 owned 配置直接复用，不扫描其他项目秘密。包内的完整官方 Tunnel 客户端会自动识别；缺失时须提供完整官方发布目录中的 EXE 路径并保留其伴随文件。

非交互执行示例（替换的是 ID 和路径，不是 key 正文）：

```powershell
.\scripts\install.ps1 -NonInteractive `
  -TunnelId 'tunnel_自己的ID' -OrganizationId '自己的OrganizationID' `
  -TunnelEnv 'C:\自己的安全目录\tunnel.env'
```

`-TunnelClient` 可覆盖客户端完整路径，`-DataDir/-CodexHome/-CodexCommand` 可指定安装目标，`-Autostart` 仅在明确需要登录自启时使用。配置不完整时本机注册保留，不启动服务。配置完整时执行 setup、run、doctor；重复执行复用本实例，已有服务不启动第二份。更改运行中的 Tunnel 参数须先停止本实例再重跑；同名他人物料仍由原有归属检查拒绝覆盖。

## 私有插件与真实验收

1. 安装诊断显示 Tunnel `ready` 后，在 [ChatGPT Plugins](https://chatgpt.com/plugins)使用自己的 workspace 添加或配置 custom MCP server，选择 **Tunnel** 和相同 tunnel ID，保持私有。当前专用头方案的 Authentication **None** 组合需要真实核验；扫描工具与 Events，定义变化后 rescan。客户端须保持运行。`ready` 不等于插件或 Dot 已成功调用。
2. 新建 Codex 对话或重启，实际发现全部九个 caller 工具：`dots_submit`、`dots_list`、`dots_get`、`dots_wait`、`dots_message`、`dots_followup`、`dots_cancel`、`dots_status`、`dots_ack_result`；随后真实调用 `dots_status`。只看到 MCP 注册或 Skill 文件不能算已加载。
3. 让自己的目标 Dot 发现 worker 工具，并订阅 `task.available`、`queue=tasks`。callback、签名 secret 和 challenge 由平台提供，不能编造。详情见 [Dot 执行说明](Dot执行说明.md)。安装器不替 Dot 创建订阅。
4. 委派一条无副作用的合成文本任务，例如“只把这三句测试文字合并成一段，不读文件、不运行命令、不发消息”。保存 task_id，在 Codex 实际读取结果；再执行一次需要用户回答的澄清任务，确认同一 task_id 继续。真实调用、入队、领取、结果读回和用户认可分别核对，尚未执行的均保持 pending。

安装器显示待办并执行本机诊断，不自动提交测试任务，也不会写入虚假的验收成功记录。维护与停机见 [维护与故障排查](维护与故障排查.md)。
