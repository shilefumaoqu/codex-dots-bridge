# 发布门禁

本页是 alpha.7 发布必须执行的检查列表，不是通过报告。逐项以当批实际证据记录完成、失败、跳过或未验证；具体结果以该版本 Release 验收记录为准，不能从静态包文档推断检查通过。

## 发布内容

- 公开文档限制为 `scripts/public-release-policy.json` 列出的九个通用指南，以及 README、许可、安全和贡献等根文档。公开素材仅引用实际存在的星渡素材。
- 排除运行数据、配置、密钥、原始对话、个人身份、私人安装路径、业务正文、私人产物链接及非公开开发流水账。
- 核对源码/运行程序/安装包版本 `0.2.0-alpha.7`，README 中英文能力、步骤、边界一致，所有本地链接指向实际公开文件。
- 保留 MIT、npm 生产依赖、Node 与官方 Tunnel 的来源、许可和伴随声明；校验载荷及分发资产。

## 代码与包检查

- 类型检查、构建、适用测试与必要官方 Codex 安装覆盖完成；跳过项明确记录。
- 对本批差异安排实际代码审查，说明模型指定参数、实际审查方式、未解决项和验证边界。
- Setup 复用同批已校验 ZIP 载荷；校验构建出的 EXE、SHA256 与版本，不发布开发工作区原始材料。
- 最终 `check-package.ps1 -RequireEvidence` 必须传入 `-SetupExe` 实际安装器，同时绑定 `-SourceCommit`、`-SourceZip`、`-WindowsZip`、`-ReleaseNotes` 与私有 `-Evidence`。alpha.7 缺 Setup 即失败；后续需 Setup 的版本可显式加 `-RequireSetup`。旧版无 Setup 的 ZIP 验证兼容保留，任何版本提供 Setup 后都必须验证其摘要与安装证据。
- 证据 schema 为 1、`mode: real`，新增顶层 `setupSha256`；`installUpgradeUninstall` 需 `status: passed`、`mode: real`、同一 `setupSha256`、实际 `fromVersion`、本版本 `toVersion`，以及 `installed`、`upgraded`、`uninstalled`、`uninstallPreservedData` 全为 true。升级必须从不同旧版本到本版本，同版重装不能替代。其 `evidence: {path, sha256}` 绑定私有原始实测记录；不将 schema 通过记为实测通过。
- 最终 Setup 重新编译或字节变化后须重新绑定对应实测证据；同版本号或相同载荷 ZIP 不能复用旧 EXE 的验收。安装、升级、卸载证明与云端普通任务证明分别记录，不互相替代。
- 隔离验收包含空格路径、干净安装、重复安装、升级、外来/修改过的注册冲突、启动/停止及卸载保留数据。用户不需要全局 Node/npm。
- 密钥和配置不完整保持 pending，安装不创建虚假成功记录；自身归属检查不得放宽以绕过失败。

## 真实链路验收

- 新包 Codex 实际发现九个 caller 工具并调用 dots_status。
- 使用者自己的私有插件、Dot 与 queue=tasks 订阅实际连接，文本派单、领取、结果读回及澄清沿原 task_id 继续。
- 可选本机读取按全部 next_offset 取齐，核对持久页完整标记并披露 source_complete=false。
- 可选发送在明确授权的空闲样本中关联同 request_id 的新回合 exact_turn_reply；忙、离线或未知样本永久跳过，不补发，发送不明不盲重试。
- 升级后按原 ID 读取旧任务、结果与 ACK；卸载后保留独立数据。备份恢复单独记录，云端恢复不以本地测试代替。

既有 glint.7 的普通文本闭环与 667 块长记录传输是历史基线证据，不等于本次 Setup 或所有账号通过。不能声称全部 2100 万字符语义处理、72 小时稳定性、官方稳定发送或并发能力。

## 外部发布

完整资产与 Release 正文准备后，确认具体仓库、当前可见性、commit、Tag 和预发布附件的授权；未授权不 push、不建 Release，不自动改变仓库可见性。发布后检查实际下载和 SHA256。尚未通过的新包不得借用旧包检查结论。
