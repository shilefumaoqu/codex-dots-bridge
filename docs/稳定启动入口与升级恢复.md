# 稳定启动入口与升级恢复

alpha.24 为本地候选；本页描述实现与验证边界，不代表已部署、已通过正常登录或真实 Dot 验收。

## 登录启动

标准用户 Startup 中的 `CodexDotsBridge.lnk` 指向固定 `Setup\CodexDotsBridge.Launcher.exe --autostart`，工作目录和图标目标不含 payload 版本。Launcher 不常驻、不申请管理员权限，不接受外部命令字符串。它读取已提交的安装 state，核验目录、实例注册、config 绑定、包身份与直接启动文件，再分别派生对应版本的 Node 启动入口与托盘。存在未完成事务时拒绝启动，绝不从事务的 `new_root` 猜测当前版本或创建另一实例。

Launcher 协议为 `launcher-1`，不随 payload 版本变化。程序身份使用安装 state 中记录的实际二进制 hash；构建还记录源码 hash。源码身份相同且现有二进制 hash 仍匹配时，即使 Framework 编译器 PE 时间戳不同也保留现有 exe。源码确有变化才按新包身份切换，回滚保留旧二进制材料。

相同且归属可确认的 `.lnk` 只读取，不再次 `Save`，保留字节与修改时间。Windows 的 StartupApproved 状态只读：明确禁用保持禁用，未知不当作启用；不改注册表，不另换名称恢复启用。旧 VBS 若被 Windows 禁用，迁移在停止旧后台前返回 `legacy_autostart_disabled_requires_user_migration`，等待用户决定。

Launcher 的标准输出 JSON 回执固定使用 UTF-8、无 BOM，不依赖系统控制台代码页。回归覆盖中文路径的实际创建、重复维护和移除，以及含非 CP936 字符和 emoji 路径的只读回执。后者不表示 Windows WScript.Shell 能在这些路径创建快捷方式：本机 COM 对含非 CP936 字符的目标路径可返回 `E_INVALIDARG`，此时仍按登记失败处理，不进入停止旧后台阶段。

初次创建／迁移仍是正常启动登记，可能被系统防护拒绝。实现不关闭防护、不变更权限、不通过另一写入者重写被拒 VBS。新入口创建和回读安排在停止原后台之前；若失败，原 MCP、任务、订阅与运行实例不进入卸载／停止流程。只有新入口已确认并保存恢复材料，才在后续提交阶段移除精确匹配的旧项。

托盘继续提供一个登录自启开关；切换只影响登记，不改变当前后台运行。安装事务进行中禁止托盘变更登记。外来项、用户改动和不明回执保留现场。

## 未完成事务与回滚

回滚分别尝试注册／配置、后台、托盘、开始菜单快捷方式和启动登记恢复。某项失败不跳过独立阶段；后台仅在原安装绑定可核验时恢复。存在未解决项时保留 `.setup-transaction.json` 及错误，不以“退出码成功”掩盖缺口。若迁移旧 VBS 后又发生后续失败，不能保证受防护策略限制的旧 VBS可重建；保留事务并报告自启缺口，不切换写入者重试。

对于“原服务、原注册已经恢复，但 alpha.23 事务残留，自启 VBS 缺失”的状态，不重复运行旧的整段 Rollback。使用新候选的生命周期脚本显式核验：

```powershell
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <新候选的setup-lifecycle.ps1> -Action RecoverRollback -InstallDirectory <原Setup目录> -InstallerIdentity <原实例ID>
```

此命令要求已提交旧 state、MCP／Skill 和运行绑定匹配；config 除根级动态 `endpoint` 外的持久字段必须结构一致。若旧实例已正常重启，须同时核对原 supervisor／bridge 的进程身份，并用原 caller 凭据鉴权当前本机端点；检查期间配置仍须保持原字节。确认后的活配置不会被旧快照覆盖，重复 Rollback 也不会停止该实例；若注册尚未恢复则保留事务并要求先受控解决注册。它登记核验结果后保留 pending，返回 `recovery_verified_requires_explicit_defer`。确认只暂缓缺失的自启登记后，同一命令增加 `-DeferAutostart`：完整原事务先复制到 `Setup\recovery\rollback-*.json`，安装 state 记录确切路径、SHA-256 和自启缺口，写回成功后才移除当前 pending 入口。

下一次升级校验并显式引用该恢复材料，不静默丢弃；成功 state 记录由哪个版本接续解决。恢复材料内容保持原样。配置、归属、证据 hash 或运行状态不明时停止受影响步骤，不删除任务数据、不恢复旧任务数据库、不改订阅。

## 诊断与验收

Node 启动阶段记录沿用 `<data-dir>.startup.json`。原生 Launcher 在 Node 尚未启动前被拒时，将时间、安全错误码及 `failed`／`dispatched` 结果保存在 `Setup\.launcher-diagnostics.json`；记录有归属标记、大小上限及原子替换，不保存原始命令、任务或凭据，写诊断失败不改变启动结果。近期原生失败可以通过现有状态说明／复制诊断读取。`dispatched` 仅表示派生入口，不表示服务就绪或业务成功。

同次开机恢复仍使用原有 20 秒探针期限。锁门之前与持有精确旧锁之后分别重新采样进程，每阶段将需刷新的空命令 PID 与记录 PID 去重，合并为一次新鲜 CIM OR 查询；不跨阶段复用快照。目标身份、CreationDate、端点、锁／元数据复查以及未知即拒绝的条件保留。

定向测试包含真实隔离 `.lnk` 读写、同登记字节／mtime 保持、合成跨 payload MCP／Skill 升级与故障恢复、Windows 禁用模拟、登记被拒时原运行材料不变、分项回滚及显式事务证据承接。测试 APPDATA 位于临时目录；Windows 注册表禁用测试使用适配器，不修改用户真实禁用设置。

最终安装 EXE、完整包身份、正常用户登录及真实 Dot 链路仍需分别验收。隔离或合成样本不能代替生产验收。
