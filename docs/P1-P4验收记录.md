## 记录规则与公共字段

结果状态统一用：`待执行`、`执行中`、`部分通过`、`通过`、`失败`、`受阻`、`不适用（说明理由）`。状态无证据不得升级。首次验收前写入实际版本/commit、开始时间和唯一 run_id；后续修改程序时记录变更点及受影响的重验项。

每项保留以下字段，原始关联证据放在源码外的受保护数据目录，公开文档只留脱敏路径与摘要：

| 字段 | 必须记录的实际值 |
| --- | --- |
| 身份与环境 | case_id、run_id、版本/commit、Windows/Node/Tunnel/MCP SDK/Codex 桌面或 CLI 版本、时区 |
| 提交 | 提交原文、独有 token、idempotency_key、task_id、逻辑会话标签、提交入口、入队时间 |
| 通知与执行 | subscription ID、event ID、事件收件时间/HTTP 状态、attempt、领取时间、input_revision、检查点 revision/acknowledged |
| 澄清与变更 | question_id、问题原文、真实用户答案及来源时间、message_key、更新后的 revision、实际采用 revision |
| 结果 | result_id、准确正文/data/链接、accepted_as_final、入库时间、预期/实际逐字段比较 |
| 取回与认可 | Codex 返回正文的实际入口/时间、result_read_at、codex_received ACK 时间、用户明确认可/不认可的来源及 user_accepted（未评价时不填） |
| 收尾 | 终态、重复执行/迟到结果数量、异常、实际停止回执、证据私有保存位置、未验证边界 |

claim_token、runtime/worker/caller key、回调 URL/signing secret、个人 Dot/账号身份不进入公开记录。事件 HTTP 2xx、工具 accepted、任务领取、结果入库、Codex 取回和用户认可分别记录。调用 `dots_get` 或 `dots_wait` 真正返回指定终态结果会记录 caller read；worker `get_task` 不算 Codex 取回。读取并展示准确正文后再 ACK，不能仅用 ACK 接口成功反推展示发生。

## 十个无副作用任务

每项只处理提供的文字，禁止联网、读取本机文件、调用业务账号、发送消息、操作应用或执行命令。任务工具的领取/检查点/结果入库属于验收路径；这里不要求 Dot 使用 Windows shell。各项分别生成新的 `TXX_TOKEN`，替换所有同名占位变量；同项丢包重试复用原 token 和 idempotency_key，不生成新任务。默认 `safe_to_retry:false`。
