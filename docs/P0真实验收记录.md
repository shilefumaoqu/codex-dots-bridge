# P0 真实验收记录

验收日期：2026-10-09。版本：0.1.0-p0.1。本文只保留脱敏技术证据，后续产品验收见[P1–P4记录](P1-P4验收记录.md)。

**官方 Secure MCP Tunnel → MCP Events → 现有 Dot → 本机结果入库 → Codex 取回的两条真实无副作用样本通过。**

## 环境

Windows x64、私有 Node 24.21.0、MCP server 2.3.1 / node 2.1.1、官方 Tunnel Windows amd64 0.0.16、私有 MCP 插件及真实 Dot。worker 不依赖 Windows shell。本阶段通过维护 CLI 访问 caller，桌面自动注册在后续阶段验证。

## 结果

| 层次 | 已执行证据 |
| --- | --- |
| Tunnel | health/ready 成功，实际云端工具调用通过 |
| 发现与认证 | 七个 P0 worker 工具和 task.available；私有 Tunnel 注入独立 worker 头的组合可用，不用于公网服务 |
| Events | queue=p0 的真实订阅、callback challenge、active 持久化；三次事件首次投递均 HTTP 200 |
| echo | Dot 领取、checkpoint、回传随机合成文本；结果与输入精确一致 |
| 澄清 | 固定 blue/green 合成问题；真实回答经 Codex 写回，原 task_id revision 1→2 后重新领取完成，答案一致 |
| 取回 | 两条结果经 caller 读取、展示及指定 result_id ACK；ACK 不等于产品认可 |
| 停止 | unsubscribe 后 active=false；测试 Bridge/Tunnel 进程退出、端口关闭、锁释放 |
| 重启 | 正常重启后两条结果的 ID、正文、revision、领取次数与 ACK 一致；停用订阅及三条收件记录保留，云端再次读回一致，无重复派单 |

合计两个任务、三次任务事件、三次领取、两个结果、两次 Codex ACK。澄清后的第二次领取属于正常续接。执行端领取、提问及完成由真实 Dot 调用，未以本机模拟 worker 代替。

## 限制

测试期间曾出现官方客户端长轮询超时/network_error，退避后恢复。没有完整长期观察；已完成任务和停用订阅的正常重启持久性不能替代活跃任务/订阅中断恢复。

该阶段复用52项本地测试与 Codex review gpt-6.1-sol / high 的证据，不把协议成功称为 v1.0。账号权限必须由各部署者独立核验。运行密钥只交给官方 Tunnel 子进程，数据权限限当前用户和 SYSTEM；秘密、真实连接 ID、原始日志与任务资料不进入公开记录。
