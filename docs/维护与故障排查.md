# 维护与故障排查

当前 alpha 版本为 `0.2.0-alpha.21`，最终包安装验收、专门审查及本机部署已完成。正向合成任务和用户直接发起的反向单样本取得真实结果；自然 Events 及时领取和宿主目录拒绝根因仍待闭环，见[alpha.21 启动恢复验收](alpha21启动恢复验收.md)。alpha.20 的托盘与安装维护结果保留在其[历史验收](alpha20托盘验收.md)，不作为本版新证据。

首次安装时 autostart 默认 unchecked，启用后 Startup VBS 在当前 Windows 用户登录时启动服务与托盘，不承诺登录前启动。alpha.21 在严格核对同用户与实例归属、PID 创建时刻、状态、端点及本实例残余进程后处理已证实的同次开机陈旧锁和 PID 复用；不明时保留现场，不结束无关 PID。升级保留已有自启设置；`run --stop` 仅停止当前服务，下次登录按设置启动。只迁移已核实属于本实例的旧登录入口并保留回滚材料。alpha.19 旧版完整双锁/旧 boot 的规则保留在其[历史验收](alpha19启动恢复验收.md)，不替代 alpha.21 的实现与测试。

## 日常入口

| 维护命令 | 作用 |
| --- | --- |
| setup | 初始化与 owned MCP/Skill 注册；可选登录自启及本机访问设置 |
| run / run --stop | 启动或协作停止本实例后台服务 |
| status / doctor | 读取真实运行状态及注册/连接诊断 |
| status --tray | 读取托盘白名单状态、当前 CLI/实际服务版本和待处理任务数 |
| setup --autostart-state enabled\|disabled | 单独切换登录自启，回读设置，不改变当前运行 |
| tasks | 按原 task_id 查询任务 |
| resolve | 依据证据决定待核对任务 complete/fail/retry |
| backup / restore | 受保护离线备份与恢复 |
| uninstall | 移除本项目注册/自启，默认保留数据 |

上述为现有 Bridge 维护 CLI，精确调用方式以安装包 `--help` 为准。Setup 的入口和参数以实际发布资产为准。`stdio` 是 Codex 内部入口，其 stdout 不能混入日志。当前没有并发配置 API。

## 托盘状态与自启

从开始菜单打开 Codex Dots Bridge 托盘。界面三行分别对应本地服务、云端连接和 Dot 订阅，并显示状态与版本。托盘程序集、维护 CLI 和实际运行服务版本分别读取，不同版本以 amber 提示并列出；未取得实际服务版本时保留未知，不用托盘版本补齐。绿色要求鉴权查询和连接诊断成立，PID 存活只作生命周期线索。

| 托盘状态 | 含义与处理 |
| --- | --- |
| 连接就绪（green） | 服务、云端连接及有效 Dot 订阅已核验；不代表具体任务成功 |
| 后台已停止（gray） | 正常清理与锁释放已确认；云端和 Dot 显示“未检查”，可启动后台 |
| 正在启动 / 正在停止（amber） | 等待状态更新，当前操作不重复发起 |
| 停止尚未确认（amber） | 停止请求已发出但清理结果未确认；核对原实例，不据此宣布停机完成 |
| 等待连接设置（amber） | 按安装连接入口完成设置 |
| 连接待恢复（amber） | 核对云端连接及有效订阅 |
| 状态未知（amber） | 查询超时或身份/诊断不明确；启动和停止控制禁用 |
| 版本未同步（amber） | 核对分别列出的当前 CLI 和实际服务版本，不冒充同步成功 |
| 后台故障 / 启动失败（red） | 查脱敏诊断和本实例记录，保留任务及恢复材料 |

右键“登录 Windows 后自动启动”直接切换设置；开启将在下次登录分别隐藏启动后台与托盘，关闭只移除本项目拥有的精确 Startup 入口。服务正在运行时也可切换。设置失败、外来/用户修改的入口或并发设置冲突应保留并报告，不覆盖未知文件。退出托盘仅结束界面；后台和任务保持原状态。停止后台前核对 queued、running、waiting_input、cancel_requested 与 reconciliation_required；查询失败时任务数为未知，不当作零。

## 分层诊断

| 现象 | 行动与边界 |
| --- | --- |
| 找不到 dots_* | doctor 核对注册，另检查 Codex MCP 列表；新建对话或重启后实际发现工具 |
| bridge_unavailable / service_not_started | status 核对本实例 endpoint 和进程，再启动原实例；不另派任务 |
| Tunnel 未 ready | 核对官方 endpoint、runtime key 有效期与工作区关联，仅查看脱敏诊断 |
| 入队无人领取 | 核对 Dot 订阅 active、queue=tasks 与事件收件；accepted 不代表已执行 |
| waiting_input | 读取真实 question_id，将用户答案写回原 task_id |
| 补充未采用或结果过时 | 核对 revision 与 Dot 检查点，不把保存当采用 |
| cancel_requested 未结束 | 核对原执行者及停止回执，不自动重派替代任务 |
| reconciliation_required | 核对 attempt、外部动作及迟到结果后明确 resolve |
| 本机对话工具缺失 | 核对 read/read-send opt-in、生效状态及插件重新扫描；不绕过关闭设置 |
| native_reader_* / context_too_large | 官方只读接口失败或历史超限；保留原请求回执，不截断冒充读全 |
| 本机发送 awaiting_delivery_choice | 说明状态，由人选择；同 request_id/thread/text 填写实际支持的 delivery_mode |
| 本机发送 skipped | 离线/未知或旧版 busy 是本次终态，不等待上线补发 |
| send_outcome_unknown / uncertain | 可能已执行，沿原 request_id 核对，不换键重发 |
| dispatch_context 为 legacy_unknown | Bridge 没有该旧提交的 caller 来源记录；不可从任务正文或历史推断授权，也不要回填来源 |
| delivery_window_expired / interrupted | 限时发送窗口已过期或因服务重启中断；不延长窗口、不换请求编号续发 |
| delivery_window_input_mismatch | request_id 对应的 thread_id 或正文摘要不匹配；保留回执并核对原试验输入 |

私有 IPC 的 ipc_connect_unavailable、ipc_initialize_failed、ipc_owner_discovery_failed、ipc_snapshot_unavailable 分别标识连接、初始化、桌面实例定位及状态快照阶段。初始化等待上限为 2 秒，owner discovery 独立等待上限为 12 秒，为 Router 的 10 秒 discovery 等待保留有限余量；发送后的 start ACK 仍最多等待 15 秒。alpha.14 的 owner 核对、可选加载、忙碌等待与发送 ACK 共享投递前最多 60 秒预算；有效匹配 ACK 已持久化后，才开始独立最多 60 秒的本回合回复等待。两阶段均受已有单请求五分钟 delivery_window guard 剩余预算与 abort 限制，不延长窗口，不自动重试。读取仍保持独立的 60 秒上限。

native_owner_unavailable 仅表示本次 owner discovery 收到明确的 no-client-found 回包；只有此精确错误且请求尚未发送才触发一次导航。ipc_owner_discovery_failed 表示该阶段失败或本地等待超时，不触发导航。不能据此断言对话不存在或需要登记。历史读取独立使用官方 App Server，不要求该 owner 在线；可能已发送但 ACK 不明时不重发。

alpha.17 对明确 owner 缺失且尚未发送的新请求，向现存 Windows Store Codex 实例导航一次，然后在原 60 秒投递预算与 abort 内每次阴性查询结束后间隔 250ms 重新发现同 UUID 的原 owner 和状态。只有取得新鲜 snapshot 才尝试一次发送；私有 Router 发起时的 `canHandle` 单次快照不会随角色更新重评，因此重新发现 owner 不代表同次请求进入发送路由。native_desktop_offline 不会冷启动；native_window_ambiguous 不猜实例；native_navigation_unconfirmed 不重发导航。导航 ACK 不是发送 ACK，也不证明未加载目标真实往返通过。导航可能切换可见对话并继续已有队列，应核对本次新请求的独立回执。

选择下一回合后，等待同时绑定原 owner 与原回合；next_turn_owner_changed 表示处理端身份已改变，next_turn_changed 表示出现其他回合，均结束等待，不自动重发。waiting_next_turn 只表示尚未发送的 Bridge 等待；实际发送后切回 pending，再等待该次新回合的独立回复。

awaiting_delivery_choice 保留未发送请求，说明状态后由人选择；waiting_next_turn 仅为 Bridge 最多 60 秒等待，不是原生排队已接受。next_turn_changed、next_turn_identity_unavailable、next_turn_wait_expired 分别标识回合已变、无法可靠关联或期限结束；离线、断线、重启不自动继续。current_turn_delivery_unsupported 是当前私有协议的能力限制，不是缺少逐对话授权。旧 skipped 请求仍为原终态，发送不明不换编号重试。

alpha.14 的 next_turn 等待共享投递前最多 60 秒预算，不能额外再获得完整 60 秒。可选 timing.stages_ms 仅返回 owner_lookup/autoload/busy_wait/send_ack/reply_wait 中实际测得的毫秒耗时；未测项省略，不输出目标、owner、目录、正文或凭据。排障须分别核对服务定义、客户端目录和 Dot 实际采用的定义，安装或刷新成功不能代替实际采用。来源判断是外部未定位项，不改两个 false 字段或提示词声称修复。

限时窗口的决策时钟来自 `get_task.server_clock` 的 Bridge 主机 UTC 和剩余毫秒，Dot 自报时钟不作为证据。窗口仅在合法 caller 鉴权后随原业务事务保存；同次重试不刷新来源时间或截止。窗口发送必须绑定 request/target/text 并通过发送入口和实际投递前检查；截止附近出现不明结果时，可能已经发生外部发送，沿原 request_id 核对，不用新编号重试。普通任务不要求窗口，也不需逐任务登记。

## 停机、备份与恢复

先读取活跃任务，再协作停止本实例，核对 Bridge、supervisor、Tunnel 和 guardian 退出。停止本机服务不等于云端工作停止；未知任务仍按原 ID 核对。不要批量结束其他 Node/Codex 进程。

旧版 `backup --to PATH` 生成包含恢复凭据的受保护目录。恢复须先确认来源、目标、同一账号/Dot及停机影响，使用 `restore --from PATH --data-dir EMPTY_NEW_TARGET`；所有源/目标相关实例先停止，目标必须为空，不覆盖既有数据。仅当前用户与 SYSTEM 可访问备份。

恢复保留实例身份、凭据、订阅及待投递事件，启动可立即投递旧 callback，必须在启动前核对原工作区及订阅。恢复后检查任务数量、原 result_id、revision、ACK 与认证隔离，不能以退出码替代结果回读。不支持跨账号/Dot迁移。

resolve 请求为 `{task_id,resolution_key,decision,basis,result?}`，decision 是 complete/fail/retry。complete 需要准确结果；retry 可能重复外部动作，须已有相应授权。没有回包不能作为自动重派依据。

## 升级、卸载与冲突

升级前保留受保护备份，停止原实例，沿原数据目录重新注册及启动，读回原任务。Setup 的操作契约为程序与数据分离、升级/卸载保留数据；实际版本和环境的验收以 Release 记录为准，见[发布与升级](发布与升级.md)。

alpha.20 的安装器 Prepare 在停机前检查上述待处理状态，有任务即拒绝升级。升级仅关闭身份已核实的同实例旧托盘，并统一更新安装入口、服务、Startup 与开始菜单。程序和注册回滚不还原数据库；保留的原任务须按原 ID 回读。隔离安装的通过不代表本人实例已切换；原后台正在运行时升级须恢复新后台，未配置云端时显示待设置，原来停止时保留停止。

外来同名注册、被用户修改的 Skill、归属不明的文件应保留并报告，不能自动删除或覆盖。不要重生成 token 或清空数据来修复配置。完整清除数据属于独立破坏性操作，需要明确授权及恢复条件。

安装/升级维护入口遇到 stale_lock_requires_recovery、stale_service_lock、stale_supervisor_lock 或 orphaned_children_require_recovery 时，先核对锁记录、进程归属、创建时刻与 endpoint。alpha.21 通过同版恢复帮助器处理已证实的陈旧状态；运行或身份未知、仍有本实例残余进程等情形保持阻断。它不会把复用 PID 当成自己的后台，也不会结束无关进程或覆盖数据库。无法自动确认时保留现场；如需人工维护，只能在确认精确实例及全部子进程已退出后，将其 owned 旧锁移至受保护恢复目录留证。不用通配符，不改数据库和密钥。alpha.19 的旧 boot 完整双锁门槛是历史实现，不能据此手动删 alpha.21 未确认的锁。
