# 维护与故障排查

默认数据目录为 `%LOCALAPPDATA%\CodexDotsBridge\data`，独立于安装程序。数据、密钥、数据库、备份和原始业务内容不得上传公开 Issue。alpha.7 Setup 的生命周期验收结果以该版本 Release 记录为准，本页说明维护契约。

## 日常入口

| 维护命令 | 作用 |
| --- | --- |
| setup | 初始化与 owned MCP/Skill 注册；可选登录自启及本机访问设置 |
| run / run --stop | 启动或协作停止本实例后台服务 |
| status / doctor | 读取真实运行状态及注册/连接诊断 |
| tasks | 按原 task_id 查询任务 |
| resolve | 依据证据决定待核对任务 complete/fail/retry |
| backup / restore | 受保护离线备份与恢复 |
| uninstall | 移除本项目注册/自启，默认保留数据 |

上述为现有 Bridge 维护 CLI，精确调用方式以安装包 `--help` 为准。Setup 的入口和参数以实际发布资产为准。`stdio` 是 Codex 内部入口，其 stdout 不能混入日志。当前没有并发配置 API。

## 分层诊断

| 现象 | 行动与边界 |
| --- | --- |
| 找不到 dots_* | doctor 核对注册，另检查 Codex MCP 列表；新建对话或重启后实际发现工具 |
| bridge_unavailable / service_not_started | status 核对本实例 endpoint 和进程，再启动原实例；不另派任务 |
| Tunnel 未 ready | 核对官方 endpoint、runtime key 有效期与工作区关联，仅查看脱敏诊断 |
| 入队无人领取 | 核对 Dot 订阅 active、queue=tasks 与事件收件；accepted 不代表已执行 |
| waiting_input | 读取真实 question_id，将用户答案写回原 task_id |
| 补充未采用或结果过时 | 核对 revision 与 Dot 检查点，不把保存当采用 |
| cancel_requested 未结束 | 核对原执行者及停止回执，不自动重派替代任务 |
| reconciliation_required | 核对 attempt、外部动作及迟到结果后明确 resolve |
| 本机对话工具缺失 | 核对 read/read-send opt-in、生效状态及插件重新扫描；不绕过关闭设置 |
| native_reader_* / context_too_large | 官方只读接口失败或历史超限；保留原请求回执，不截断冒充读全 |
| 本机发送 skipped | 忙/离线/未知为本次终态，不等待上线补发 |
| send_outcome_unknown / uncertain | 可能已执行，沿原 request_id 核对，不换键重发 |

私有 IPC 的 ipc_connect_unavailable、ipc_initialize_failed、ipc_owner_discovery_failed、ipc_snapshot_unavailable 分别标识连接、初始化、桌面实例定位及状态快照阶段。初始化等待上限为 2 秒，owner discovery 独立等待上限为 12 秒，为 Router 的 10 秒 discovery 等待保留有限余量；发送后的 start ACK 仍最多等待 15 秒。各阶段均受原请求整体 deadline 和 abort 限制，不延长整体截止时间，不自动重试。

native_owner_unavailable 仅表示本次 owner discovery 收到明确的 no-client-found 回包；ipc_owner_discovery_failed 表示该阶段失败或本地等待超时。这两类结果均不能据此断言目标离线、对话不存在或需要登记。等待预算修正不负责恢复缺失的 owner：未找到 owner、忙或状态不明仍跳过，不唤醒、不 resume、不等待上线补发；可能已发送但 ACK 不明时也不重发。新版历史读取独立使用官方 App Server，不要求该 owner 在线。

## 停机、备份与恢复

先读取活跃任务，再协作停止本实例，核对 Bridge、supervisor、Tunnel 和 guardian 退出。停止本机服务不等于云端工作停止；未知任务仍按原 ID 核对。不要批量结束其他 Node/Codex 进程。

旧版 `backup --to PATH` 生成包含恢复凭据的受保护目录。恢复须先确认来源、目标、同一账号/Dot及停机影响，使用 `restore --from PATH --data-dir EMPTY_NEW_TARGET`；所有源/目标相关实例先停止，目标必须为空，不覆盖既有数据。仅当前用户与 SYSTEM 可访问备份。

恢复保留实例身份、凭据、订阅及待投递事件，启动可立即投递旧 callback，必须在启动前核对原工作区及订阅。恢复后检查任务数量、原 result_id、revision、ACK 与认证隔离，不能以退出码替代结果回读。不支持跨账号/Dot迁移。

resolve 请求为 `{task_id,resolution_key,decision,basis,result?}`，decision 是 complete/fail/retry。complete 需要准确结果；retry 可能重复外部动作，须已有相应授权。没有回包不能作为自动重派依据。

## 升级、卸载与冲突

升级前保留受保护备份，停止原实例，沿原数据目录重新注册及启动，读回原任务。Setup 的操作契约为程序与数据分离、升级/卸载保留数据；实际版本和环境的验收以 Release 记录为准，见[发布与升级](发布与升级.md)。

外来同名注册、被用户修改的 Skill、归属不明的文件应保留并报告，不能自动删除或覆盖。不要重生成 token 或清空数据来修复配置。完整清除数据属于独立破坏性操作，需要明确授权及恢复条件。

stale_service_lock、stale_supervisor_lock 或 orphaned_children_require_recovery 先核对锁记录、进程路径、参数与 endpoint。只有确认精确本实例及全部子进程已退出，维护者才可将相关 owned 旧锁移至受保护恢复目录留证。不用通配符，不改数据库和密钥；无法确认时保留现状。
