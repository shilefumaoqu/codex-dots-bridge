# 维护与故障排查

生产默认数据目录为 `%LOCALAPPDATA%\CodexDotsBridge\data`，P0 历史目录为 `p0`。源码、安装目录、运行数据与密钥分别保存；不要把完整数据目录上传 Issue 或 GitHub。

## 日常命令

| 命令 | 目的 |
| --- | --- |
| setup | 默认检查冲突并注册 MCP/Skill；--no-register 仅本地初始化；--autostart 可选登录自启 |
| run | 启动隐藏后台 supervisor；run --stop 协作停止本实例；run --foreground 仅开发 Bridge |
| status | 读真实本机运行状态 |
| doctor | 检查路径、注册、数据、认证隔离和连接情况 |
| tasks | 查询已有任务及其真实 task_id |
| resolve | 对待核对任务做明确恢复决定 |
| backup | 生成包含恢复所需数据/密钥的受保护备份 |
| restore | 在停机和范围核对后恢复备份 |
| uninstall | 只移除本项目注册与自启；默认保留数据 |

精确参数以已安装候选包的 `--help` 为准；版本不匹配时先核对，不沿用历史 P0 临时命令。`stdio` 是 Codex 的内部入口，不应把日志写到其 stdout；P0 `src/cli.ts` 只用于历史探针。

## 分层排查

| 现象 | 核对与行动 |
| --- | --- |
| Codex 看不到 dots_* | doctor 核对安装记录，另用 codex mcp list --json 检查真实 MCP 注册和路径；新建对话或重启 Codex，实际发现工具再判定加载成功 |
| service_not_started / bridge_unavailable | status 查真实进程和 endpoint；使用 run；不新建任务补偿 |
| Tunnel 未 ready | 核对官方 Tunnel 当前 endpoint、runtime key 有效期与工作区关联；查看脱敏日志，按官方入口重新授权 |
| worker 401 | 核对 Tunnel 的独立 worker 头；不要用 caller 或平台 key 替代 |
| 入队但无人领取 | 查看 Dot 订阅 active、filter=tasks 与事件收件；事件 accepted 不证明执行者在线 |
| waiting_input | 读取 question_id，在 Codex 展示问题，将真实答案写回原 task_id |
| 新输入已保存但结果过时 | 核对 Dot 检查点与采用 revision；不要声称更正已即时生效 |
| cancel_requested 长期不变 | 查询旧执行者及租约；未有 ack_cancel 不声称取消完成 |
| reconciliation_required | 停止自动重派，核对旧 attempt、外部动作和迟到结果，再 resolve |
| 本机 shell 初始化失败 | 是 Dot 原生执行能力的独立问题；按官方精确修复核验桌面构建，MCP 成功不说明已修复 |

平台登录或原生工具审批必须由相应官方入口完成，任务答案不构成授权。密钥到期时只更新专用 Tunnel 使用的安全文件，不粘贴到聊天、不修改全局环境变量。若需要重建或切换账号/公开 HTTPS 部署，先确认新的范围。

## 停止、升级、备份与恢复

维护前先读取活跃任务。关闭服务不等于取消任务；有不明执行状态时保留数据，在恢复后核对原任务，不把它们批量重新提交。停止本实例服务与 Tunnel 后确认对应 PID 退出、端口关闭及锁释放；不要批量结束用户其他 Node/Codex 进程。

升级先使用旧版本的备份命令并确认恢复材料，再停止本实例。安装路径、注册参数或 Skill 内容变化时，先由旧版 `uninstall` 移除本项目拥有的注册项并保留数据，再替换程序文件、运行新版安装脚本/`setup`、doctor、启动并按原 task_id 读回。安装器会拒绝直接覆盖修改过的 Skill 或非本项目的同名注册；保留并报告冲突，不能自动删除。不要覆盖数据目录或重新生成 token 来“修复”配置。备份含恢复所需密钥，视为敏感资料，保持 Windows ACL 仅当前用户与 SYSTEM；普通公开日志导出不包含这些密钥。

备份使用 `backup --to PATH` 生成受保护目录，不是公开 ZIP。恢复使用 `restore --from PATH --data-dir EMPTY_NEW_TARGET`，要求目标为空且相关服务已停止，不覆盖已有生产数据。恢复前明确备份来源、目标实例与停机影响；恢复后重新 setup 注册、启动并检查认证隔离、任务数量、原 result_id、revision、订阅及 ACK。恢复验证不能以命令退出 0 替代业务回读。没有完成恢复实测时保留“未验证”。

维护 CLI 的 `resolve --request JSON_FILE` 需要 `{task_id,resolution_key,decision,basis,result?}`，decision 为 complete/fail/retry。basis 必须说明核对依据，complete 还需要准确结果；retry 可能再次执行外部动作，必须已有相应授权。不能以“没有看到回包”为依据自动重派。

卸载默认保留任务数据和密钥，只移除本项目拥有的 Codex 注册、Skill、自启与程序项。同名内容无法确认所有权时停止相关移除。彻底清除数据属于独立破坏性操作，应先展示影响与恢复条件，取得明确授权。

## 非正常退出后留下的进程锁

stale_service_lock、stale_supervisor_lock 或 orphaned_children_require_recovery 表示无法直接复用旧的进程记录。程序保守拒绝自动清除，防止另一个仍在运行的实例被误替换；run --stop 返回 stopped 也不保证旧锁文件已被删除。

先保留数据，暂停对本实例的再次启动。读取 service.lock、supervisor.lock、supervisor-state.json 里的 PID/owner，核对进程可执行路径、启动参数及该实例的环回 endpoint；同时确认 Bridge、supervisor、Tunnel 与 guardian 均已退出。PID 被其他程序复用、owner 对不上、子进程仍在线或无法确认归属时，停止恢复并提交脱敏诊断，不按 PID 盲目结束进程。

只有明确确认原实例已完全停止后，维护者才将这次故障涉及的精确 owned 锁文件及过时 supervisor-state.json 移到数据目录之外新建的受保护恢复目录，保留原始内容。处理前再次回读核对；不使用通配符、不清空目录、不修改 tasks.sqlite、caller/worker 密钥或 Tunnel 配置。不能确认条件时保留现状。

随后沿原 data-dir 启动，调用 status/doctor，按原 task_id 回读任务、结果和订阅；运行中的旧尝试仍需核对，不能重新提交来补偿。此步骤属于维护者的人工恢复路径，当前没有自动清锁功能；真实系统重启后的路径留待后续使用观察。

## 提交问题

提供版本、Windows/Codex 版本、命令、预期与实际行为、脱敏状态以及关联 task_id。不要提交 runtime key、worker/caller key、claim_token、回调 URL、signing secret、完整配置、数据库、备份、个人账号/Dot 身份或业务原文。复现优先用独立无副作用文本样本；不要在不明状态下重复有外部动作的真实业务。

升级、换 Codex 原生 EXE 路径与恢复的前置条件见[发布与升级](发布与升级.md)。恢复会保留 active 订阅并在启动后继续投递，须先停所有相关实例、在启动前核对原工作区和订阅；不支持跨账号迁移。
