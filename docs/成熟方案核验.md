# 成熟方案核验

核验日期：2026-10-09。范围为 Windows 原生执行故障，以及 Codex 向现有 Dot 派单、唤醒和回收结果。本文是当时的公开来源核验，不表示后续版本状态仍相同。

## 结论

当前 Windows 故障找到了高度匹配的官方源码修复；应核验包含修复的桌面构建，不再把重启作为优先解决办法。相似 Dot 开源桥接项目存在，但本轮核验的两个候选都很早期，没有一个可以直接替换本项目并完成原目标。

任务交接方面，可复用的成熟做法是常驻服务、持久队列、稳定 ID、幂等工具和事件通知。本项目已实现其中的 P0 内核。官方 MCP Events 是已文档化的 Dot 唤醒入口；原生电脑访问与程序化唤醒是两项独立能力。文件读写恢复不等于 Codex 已能自动给 Dot 派单。

## 1. Windows 故障：已有精确机制修复

[OpenAI PR #51822](https://github.com/openai/codex/pull/51822) 于 2026-10-07 合并，标题为 Avoid sharing violations when repairing Windows runtime ACLs。旧实现对正在使用的 EXE/DLL 请求过宽的打开权限，可能触发 sharing violation。修复对文件使用 ACL 操作所需的 `READ_CONTROL | WRITE_DAC`，保留目录的特殊处理，并增加保持运行时文件打开时的回归测试。

- [修复提交源码](https://github.com/openai/codex/blob/dd12f892f1b857e5161abd33a2967125b265d550/codex-rs/windows-sandbox-rs/src/acl.rs#L546-L571)。核对了代码与新增测试；本轮没有编译或执行该上游测试。
- [0.162.0-alpha.2](https://github.com/openai/codex/blob/rust-v0.162.0-alpha.2/codex-rs/windows-sandbox-rs/src/acl.rs#L549-L559) 与[稳定版 0.162.0](https://github.com/openai/codex/blob/rust-v0.162.0/codex-rs/windows-sandbox-rs/src/acl.rs#L549-L559) 仍是旧实现。
- [0.163.0-alpha.1](https://github.com/openai/codex/blob/rust-v0.163.0-alpha.1/codex-rs/windows-sandbox-rs/src/acl.rs#L549-L569) 含修复；对应 [CLI 预发布](https://github.com/openai/codex/releases/tag/rust-v0.163.0-alpha.1) 已存在。不能把 CLI 预发布当成桌面/Dot 内置执行器已经可更新的证据。
- [Issue #52036](https://github.com/openai/codex/issues/52036) 报告相同 Windows 桌面包、`node_repl.exe` 和错误 32；报告者重启后仍失败。相关评论是用户原始复现，未发现维护者确认可用的桌面修复版本。

桌面更新渠道与CLI标签独立，不能仅凭CLI预发布存在断言桌面/Dot内置执行器可更新。使用本机文件能力前，应核对实际安装构建是否含相应修复。

不建议盲目结束所有 helper、手工重置 ACL 或全局切换 `windows.sandbox=unelevated`。后者改变隔离方式，只有其他用户的绕行实测，未验证本机 Dot 路径。必要诊断可借鉴微软 [Process Explorer](https://learn.microsoft.com/en-us/sysinternals/downloads/process-explorer) 的 Handle/DLL 搜索；[Handle](https://learn.microsoft.com/en-us/sysinternals/downloads/handle) 的强制关闭句柄功能可能使应用不稳定，不作为本项目修复手段。

## 3. 可复用的官方接入组件

[官方 MCP Events](https://developers.openai.com/plugins/build/mcp-events) 明确支持 dots：由 Dot 订阅，服务器获得 callback URL 和 signing secret；任务入库后发送稳定 ID 的签名事件，Dot 再读任务并调用工具回传。Webhook 2xx 只证明收件，最终结果必须另行入库核验。现代协议及 Events 扩展仍须实际测试。

[Cloudflare workers-oauth-provider](https://github.com/cloudflare/workers-oauth-provider) 是可选的 OAuth 组件，MIT，仓库自 2025-03 维护；[v1.2.3](https://github.com/cloudflare/workers-oauth-provider/releases/tag/v1.2.3) 于 2026-10-07 发布。当前 README 提供 MCP 2026-07-28 授权、PKCE、资源绑定与拆分授权/资源服务的示例及 workerd 端到端测试入口。它解决认证，不提供 Dot 派单或 Events 业务实现；本轮没有运行其测试。

如需避开 OpenAI Tunnel key，可将 MCP 暴露为 HTTPS 并接入 OAuth，再使用相同的 Events 与任务内核；这需要公网部署或另一种安全网络入口及相应账号配置，并非零配置替代。仅文本和结构化结果交接可通过工具完成，无须 Dot 为交接任务启动 Windows shell；真正涉及本机文件/应用的工作仍需可用的本机执行能力。这是依据协议职责提出的设计方案，尚未部署或验收。

## 4. 当前建议与最小验证

1. 优先验证 MCP Events 的纯文本 echo 闭环，再做原任务澄清；不等待 Windows shell 恢复。使用部署者自己的已关联 Tunnel，先解决实际连接入口，证明目标 Dot 能订阅、领取并回传同一任务 ID，再扩大安装与发布工作。
2. 保留已有 SQLite、幂等、租约及 Events 内核；网页派单只作验收入口，最终通过真实签名事件唤醒。若选择无需 OpenAI Tunnel key 的 HTTPS/OAuth 接入，Cloudflare 组件可作为认证候选，部署与账号边界需另行明确。
3. 本机执行能力继续核验明确包含 #51822 的官方桌面构建；版本可用后沿原任务、原输入复测，不重新派单冒充恢复。它服务于需要本机文件或应用的任务，不作为纯文本交接的必要条件。

核验时没有运行上述第三方候选或其测试。P0现有官方链路的后续结果见[P0验收](P0真实验收记录.md)；相似方案的实现和测试不能代替本项目独立验收。
