# 快速开始

当前是 Windows x64 候选版本。实际验收与稳定性观察以 [进展](进展.md) 和 [兼容性](兼容性与已知限制.md)为准，本页不代表 v1.0 验收。

## 准备

- Windows 10/11 x64，Windows PowerShell 5.1 或 PowerShell 7、本机单用户、一个自己的现有 Dot，以及可用的 Codex 桌面版或本机 CLI。
- 能使用官方 Secure MCP Tunnel、创建私有插件的账号/workspace 权限。账号登录、选择和密钥保存需要官方交互确认，安装脚本不会代办授权。
- 解压 Windows 包到用户可写的固定目录。包内私有 Node.js 24 不替换系统 Node；带 Tunnel 的包包含完整官方客户端及伴随文件。

## 下载校验与脚本执行

发布包名称含版本，下载ZIP及同名 .sha256。先用 `Get-FileHash -Algorithm SHA256 ZIP路径` 对照校验文件，再解压到固定目录；在解压目录运行 `scripts/check-package.ps1` 验证全部文件与许可。

可信包被下载标记阻止时，仅对已核验的解压目录执行 `Get-ChildItem -LiteralPath . -Recurse -File | Unblock-File`。当前 PowerShell 策略仍为 Restricted 时，可由使用者为本次进程采用 `powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\install.ps1`；这不写入全局策略。组织强制策略须找管理员，不绕过。打包和开发脚本亦需要允许执行可信本地脚本。

## 一次安装入口

在包目录执行：

```powershell
.\scripts\install.ps1
```

入口先通过归属检查安装本项目 MCP 和 Skill，再复用已有配置或引导首次连接。交互终端仅询问非秘密 Tunnel ID、organization ID 和已经安全保存的 env 文件路径，自动识别包内 Tunnel 客户端。尚未完成官方步骤时可以留空，安装保留并显示待办；完成后重跑同一入口。详细官方账号、权限和安全保存流程见 [首次连接](首次连接.md)，无需照抄历史 P0 探针。

配置完整时入口执行 `setup → run → doctor`。重复安装可修复缺失的 owned 文件，不覆盖他人同名 MCP/Skill，也不启动第二个本实例服务。若要改变运行中的 Tunnel 参数，先停止本实例，再重跑入口。

自动化或重定向终端不会等待输入。可以显式使用：

```powershell
.\scripts\install.ps1 -NonInteractive `
  -TunnelId 'tunnel_自己的ID' -OrganizationId '自己的OrganizationID' `
  -TunnelEnv 'C:\自己的安全目录\tunnel.env'
```

没有完整参数时仍完成本机注册，报告连接 pending，不启动服务。已有完整配置则无需再传连接参数。`-TunnelClient` 可以指定完整客户端 EXE 路径；`-DataDir/-CodexHome/-CodexCommand` 保持可用。登录自启仅在明确传 `-Autostart` 时启用。不要在终端、聊天或命令参数输入 key 正文；安装入口不创建账号、密钥或 Dot 订阅。

生产数据默认位于 `%LOCALAPPDATA%\CodexDotsBridge\data`；历史 P0 仍在 `p0`，不会自动迁移。源码开发先通过 `scripts/bootstrap.ps1` 准备固定 Node 24，再执行 `scripts/dev.ps1 install`、`build`；`setup --no-register` 仅用于不注册 MCP/Skill 的开发检查。

## 启动、诊断与真实验收

完整连接配置后，安装器已尝试启动并打印诊断。日常维护可以显式使用包内运行时：

```powershell
& .\runtime\node-v24.21.0-win-x64\node.exe .\dist\main.js status
& .\runtime\node-v24.21.0-win-x64\node.exe .\dist\main.js doctor
& .\runtime\node-v24.21.0-win-x64\node.exe .\dist\main.js run --stop
```

需要重新启动时执行相同入口的 `run` 命令。它启动隐藏后台 supervisor；`run --stop` 协作停止本实例 Bridge/Tunnel，不取消 Dot 任务。`run --foreground` 仅用于 Bridge 内部开发，不能替代 Tunnel 启动。

新建 Codex 对话或重启后，真实发现九个 caller 工具：`dots_submit`、`dots_list`、`dots_get`、`dots_wait`、`dots_message`、`dots_followup`、`dots_cancel`、`dots_status`、`dots_ack_result`，再实际调用 `dots_status`。缺工具时用 `doctor` 查安装记录和服务诊断，再用 `codex mcp list --json` 核对真实注册及其路径。doctor 不负责验证 Codex 当前回合是否加载或完整比对 Skill；注册记录存在不代表当前对话已加载。

然后按 [首次连接](首次连接.md)配置私有插件，让自己的 Dot 发现 worker 工具并真实订阅 `task.available`、`queue=tasks`。callback 和签名 secret 由平台提供，不自行编造。首次发送一条只整理合成文本、无外部副作用的任务，按 task_id 在 Codex 读回结果，再验证用户回答后的同任务澄清续接。

安装诊断、Tunnel ready、工具真实调用、Dot 订阅、任务结果和用户认可分别核对。安装器没有执行真实调用与任务验收，这些状态保持 pending。


## 在 Codex 委派

调用 `$codex-dots-bridge`，例如：

> 请把下面三句话整理成一段说明，交给我的 Dot。只处理这段文本，不发消息、不读本机文件。返回正文，并给我任务 ID。

Codex 会保存原 `task_id`。可以继续说“查这个任务”“补充这项要求”“回答它的问题”或“取消这个任务”。如果原任务身份缺失，先列出候选让用户选择。

本机 CLI 同样使用 `tasks submit|get|message|followup|cancel|ack|wait|list`。可通过 `--request` 读取包含工具 schema 参数的 UTF-8 JSON 文件，避免命令行编码与长正文：

```powershell
& .\runtime\node-v24.21.0-win-x64\node.exe .\dist\main.js tasks submit --request .\task-request.json
& .\runtime\node-v24.21.0-win-x64\node.exe .\dist\main.js tasks get --task '返回的task_id'
```

提交文件例如 `{"idempotency_key":"本次唯一且稳定的业务键","title":"三句话整理","input":{"text":"用户授权的实际文本"}}`。丢失回包时复用同一文件及键；不要为了超时生成新键。

等待每次最多 20 秒，当前回合默认累计 5 分钟。达到上限只报告当前状态；关闭 Codex 不取消任务。重开后按原 task_id 查询。回访默认不开启；用户明确要求后，桌面端可通过官方自动化配置每 15 分钟、最长 24 小时的回访，终态停用，真实行为仍需验证。

结果正文读回并展示后才记 `codex_received`；用户明确认可后才记 `user_accepted`。入队、事件 HTTP 2xx、领取和 Dot 聊天回复都不是完成证据。

维护与恢复见 [维护与故障排查](维护与故障排查.md)。发生超时或失租时保留原 task_id，先核对，避免重复产生外部动作。
