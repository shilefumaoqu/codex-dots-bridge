# 快速开始

当前源码版本见 [package.json](../package.json)，实际运行版本以鉴权的 `dots_status.version` 为准。发布、部署和验收范围见 [ACCEPTANCE.md](../ACCEPTANCE.md) 及对应 Release；安装成功不等于真实消息往返通过，旧版本的验收不作为当前候选证据。

## 准备条件

- Windows 10/11 x64，普通用户会话；组织限制以管理员策略为准。
- 已安装自己的 Codex，并有自己的 Dot。
- 具备 Secure MCP Tunnel、ChatGPT workspace 私有插件和 MCP Events 的实际账号权限。
- 允许本机连接官方 Tunnel/Events 的 HTTPS 服务。

Codex 订阅和 Tunnel 权限分别核对。Bridge 不调用模型 API，但 Tunnel 需要专用 runtime key。

## 安装顺序

1. 从 [GitHub Releases](https://github.com/shilefumaoqu/codex-dots-bridge/releases) 选择对应版本的 Setup 和校验文件；如仓库为私有，需登录及访问权限。核对版本、来源与 SHA256，再双击 Setup 安装。本版本 Setup 未签名，Windows SmartScreen 或组织策略可能提示或阻止运行；校验和不能替代发布者签名。
2. 先让安装器完成程序部署及本机初始化。程序与用户数据分离，新安装数据默认在 `%LOCALAPPDATA%\CodexDotsBridge\data`。升级自动复用选定 Codex Home 中已通过归属检查的原 MCP 数据目录；冲突时拒绝安装，不另建空实例。
3. 尚无 Tunnel 参数时保留连接 `pending`。从开始菜单“Codex Dots Bridge → 首次连接与维护”继续官方账号连接，按[首次连接](首次连接.md)完成自己的权限、密钥、私有插件和 Dot 订阅，无需自行寻找 Node 路径。
4. 读取真实 `status`/`doctor`，新建 Codex 对话或重启，发现九个 caller 工具并实际调用 `dots_status`。
5. 委派一条合成文本任务，按原 task_id 读回准确结果；再核对一次澄清回答沿原任务继续。注册、服务启动、Tunnel ready 和订阅 accepted 都不能代替结果读回。

Setup 的实际文件名、安装入口和命令行选项以该版本 Release 及安装器为准，不从其他版本猜参数。使用 ZIP 时，先校验包内 `scripts/check-package.ps1`，再执行 `scripts/install.ps1`；ZIP 与 Setup 的实际验收分别记录，安装完成不代表云端连接已就绪。

## 第一次派单

在已加载 Bridge 的 Codex 对话中说：

> 用 $codex-dots-bridge 把以下三句话交给我的 Dot，只做文本整理，返回三条结论和任务 ID。

继续查询时保留 task_id。等待到限不重派；Dot 提问时展示原问题并写回用户真实答案。读取并展示准确结果后才记录 `codex_received`；用户明确认可才记录 `user_accepted`。

## 可选本机对话接入

默认 `off`。需要时明确启用 `read`（只读历史）或 `read-send`（读取并可发送）。按[首次连接中的维护步骤](首次连接.md#启用可选本机对话工具)读取实际安装状态，使用包内运行时设置能力并核对生效状态；无需另装 Node/npm。变更前先确认没有在途任务，停止本实例。

启用后，人类直接给出本机对话链接并要求读取或发送指定文本，就授权该次操作，无需逐个登记。Dot 使用 `codex_read_conversation`、`codex_send_message` 和 `codex_conversation_status`；实际发现的 schema 是执行依据。

读取是官方 App Server 的持久历史分页，不要求桌面已加载目标，也不启动回合。发送通过实验性私有桌面 IPC 独立检查在线与忙闲；缺少原 owner 时可单次加载现存 Windows Store 桌面中的目标，再复核。忙碌先说明状态，由人选择下一回合有界等待；当前回合追加暂不支持可靠锁定。离线、未知、回合改变或断线就结束，不能上线补发，也不能用读取结果证明可发送。

caller 来源上下文和可选 `delivery_window` 用于限定短时发送试验，不是普通任务的要求，也不需要逐任务登记。试验时间依据 `get_task` 返回的 Bridge `server_clock`。alpha.12/13 记录是历史证据；alpha.15 已完成本机升级、新调用端握手、一条合成正向目录任务及原调用端新版切换。新版反向试验已派单，但Dot 在发送工具调用前重复要求授权，零发送，尚未通过完整往返。详见[alpha.15 状态](alpha15验收状态.md)与[任务与工具契约](任务与工具契约.md)。

更多步骤见[首次连接](首次连接.md)，工具与证据边界见[任务与工具契约](任务与工具契约.md)。
