## 本机对话读取

读取走官方本机 App Server，只调用只读 metadata/turns 分页，不恢复、不启动回合，不要求桌面加载目标。read/read-send 须显式启用；local 模式按人类指定本机 thread_id，无逐个登记。旧 targets 配置必须明确迁移，不能假装已放开范围。

持久历史包含官方保存的消息及工具记录，但可能不含原始模型上下文、压缩前材料或未持久化内容。stored_history_complete=true 与 source_complete=false 可以同时成立，必须如实解释。读取上限 60 秒、32 MiB；超限失败而不默默截断。缓存仅优化固定快照分页，释放或重启后不重新读取；新读取请求使用新 request_id。

## 本机对话发送

发送仍依赖私有桌面 IPC，与官方只读接口无关。目标桌面 owner 在线且明确空闲才能投递，读取成功不证明发送可用。写入前复核状态，但与人工同时输入不是原子操作，跨 Codex 版本可能失效。

alpha12 的 `get_task` 新增服务器顶层 `dispatch_context` 与 `server_clock`。提交来源可为 `authenticated_codex_caller`，含 `caller_attestation_of_existing_user_request`，并明确 `human_identity_verified:false`、`native_approval_granted:false`、范围仅当前委派任务；历史、资料及其他代理消息不构成授权，`legacy_unknown` 不回填。时钟字段由 Bridge 主机生成。`dots_submit` / `dots_followup` 的可选 `delivery_window` 最长五分钟，绑定准确 request_id、thread_id、正文 SHA-256 和 UTC 截止；普通任务没有强制窗口或逐项登记。调用者鉴权后于原事务保存来源，重试不刷新时间，消息来源单独记录。窗口重启即中断，须在发送入口和实际投递前检查，且当前 attempt 与最新 checkpoint/input revision 必须成立。截止附近动作可能已经发出，回执不明时沿原请求核对。alpha12 已完成本机安装升级验收；反向发送完整链路尚未通过，这些仍是候选能力。

alpha.13 的历史部署记录中，`dots_status` 返回 alpha.13、service=true、Tunnel ready、原活动订阅 1、活跃任务 0。worker MCP 的只读 `get_task` 确认 bridge_version 13/rules v6、两个 false 字段仍如实保留，旧任务仍为 cancelled。该查询 57ms 仅是本机 MCP 读取，不表示 Dot 采纳或端到端时延。此后另有一次 alpha.13 真实任务领取与规则采纳，但在工具调用前仍被要求核验来源，未调用 send/status；任务取消后的只读检查仍未发现对应 native request、turn 或 reply。该历史快照不能作为当前运行版本或 alpha.14 验收结果。

这次未调用工具不是实际观察到原生宿主拒绝。Dot 提到更高优先级来源要求，但未取得具体原生拒绝或正式平台政策证据。caller 鉴权、Events 签名和 notification binding 证明 caller/事件，不证明微信原发言者身份；继续改提示词或自行签署身份声明不是身份验证方案。

历史上已加载目标的真实往返成功记录继续保留。alpha12 新增了缺失 owner 时单次加载现存 Windows Store/MSIX 实例的分支；此前真机导航 ACK 与随后 owner 检查通过时，样本已加载，不能据此宣布未加载目标完整往返通过。只读 owner 探针未发现目标原生 owner，且未手动打开目标、读取历史或触发自动加载；这不证明未加载发送与忙碌选择通过。alpha.17 的新建未加载目标自动往返已有该版本真实通过记录；实际忙碌选择仍需单独验收；隔离缺失 owner、加载后忙碌、重复缺失及不明回执测试通过仍为其历史测试证据。portable/其他包身份和多个原实例未覆盖或明确返回歧义；不开启离线桌面。目标存在于持久历史不代表有实时投递入口。

local 模式的新忙碌请求返回 awaiting_delivery_choice，由人选择 next_turn。alpha.14 的投递前最多 60 秒，忙碌等待、自动加载与发送 ACK 共享该预算；只有有效匹配 ACK 已持久化后，才开始独立最多 60 秒的本回合回复等待。两阶段均受已有单请求五分钟窗口 guard 剩余预算限制；阶段切换、重试和用户选择不延长窗口。不覆盖原生队列；current_turn 仍明确返回能力限制。未加载目标往返已有 alpha.17 一条真实样本验证；实际忙碌续接、等待中断仍需独立证据。离线、未知、另一回合介入、断线或重启就结束，不上线补发。旧 targets 与历史 skipped 保持原契约。发送不明可能已执行，不能换编号重试；只有同 request_id 对应的新回合 exact_turn_reply 是本次结果。

## 权限与安装

alpha.20 托盘面向 Windows x64，使用 .NET Framework 4.8 WinForms；跨 DPI、其他 Windows 环境与长期常驻仍需各自的实测。三行状态是服务、云端和 Dot 订阅的脱敏观察，不展示任务正文或原始完整状态 JSON，也不证明某项任务已完成。界面版本取托盘程序集，运行时通过鉴权的本机 `/control/tray_status` 轻量接口核对 instance_id、安装与服务版本及观察时间；不一致显示 amber 并分别列出，未取得后台版时保持未知。周期刷新不启动 Node CLI，启动、停止、自启设置仍走既有维护入口。PID 存活不能建立绿色连接就绪结论。自启只读检查最多缓存 30 秒，回包单独标注其观察时间；设置文件变化使缓存立即失效。任务等待原因与带时间的最近业务事件分别呈现，业务活动不代表当前任务已完成。

右键自启开关只设置下次当前用户登录时启动服务与托盘，不改变正在运行的后台；首次安装默认未勾选，不承诺登录前启动。退出托盘只结束 UI，停止后台属于独立操作。正常停止显示 gray，云端/Dot 为“未检查”；查询超时或身份不明保持 amber 未知并禁用启动/停止。并发设置、外来或修改过的 Startup 入口失败关闭并保留现场，设置失败尽力恢复原选择。

升级保留自启关闭选择，核实同实例旧托盘后才关闭，并统一安装、服务、Startup 和开始菜单入口。Prepare 在停机前拒绝含 queued、running、waiting_input、cancel_requested 或 reconciliation_required 的升级。程序/注册回滚保留数据库当前内容，不撤销已发生的任务或外部动作；这些实现要求仍须真实生命周期验收。

可选 `timing.stages_ms` 只含已测的 owner_lookup/autoload/busy_wait/send_ack/reply_wait 毫秒耗时，未测项省略，不泄漏身份、目录、正文或凭据；它不证明发送、回复或客户端采纳。

使用者仍需自己的 Codex、Dot、Tunnel 权限、专用 runtime key、私有插件和 Events 订阅；订阅登录不能替代 Tunnel 权限。安装不会绕过平台审批。账号功能不可用时保持 pending。

Windows Setup 自带所需 Node 运行时，不要求用户安装 Node/npm；仍需用户现有 Codex。CLI 可作正向 caller；反向发送需要桌面 owner。尚不声称支持 macOS/Linux、多人、多 Dot 或并发执行配置。

本版本 Setup 未签名。下载时核对 GitHub Release 来源与 SHA256；Windows SmartScreen 或组织策略仍可能提示或阻止运行，校验和不能替代发布者签名。访问范围以仓库当前可见性为准；私有仓库需登录有访问权限的账号。

## 数据与恢复

关机、休眠、服务停止不能接收新结果。停止本机程序不撤销云端工作或外部动作。Bridge 的取消是协作停止，不是业务回滚。

默认数据与程序分离，升级/卸载按保留数据的契约执行，实际结果以对应 Release 验收记录为准。恢复仅同账号/Dot，启动前检查 active 订阅与待投递事件；不支持账号迁移。文件链接、外部工具副作用及云端恢复切换需要单独实测。

维护见[维护与故障排查](维护与故障排查.md)，工具见[任务与工具契约](任务与工具契约.md)。
