# Codex Dots Bridge 项目规划

更新：2026-10-09。本文是实施入口；要求已确认，阶段完成须有对应证据。

## 目标与范围

独立、可在 GitHub 发布的 MIT 项目，让用户在 Codex 中向一个现有 Dot 委派任务，读取结果，并完成澄清、补充、更正、关联追问和协作取消。个人及小团队各自部署独立实例；首版一个实例绑定一个 Dot，领取并发为 1。

首版仅支持 Windows x64 上的 Codex 桌面版与本机 CLI，提供本地桥接服务、CLI 和 Codex 安装向导/任务 Skill。输入输出支持文本及外部文件链接；链接是否可由 Dot 读取必须另验。不制作跨平台版本、其他 Agent 安装器、通用 SDK、多调用方管理、应用 webhook 或完整网页控制台。外部业务系统的接入属于可选使用案例，不作为插件功能或安装依赖。

部署优先使用官方 Secure MCP Tunnel。每位部署者配置自己的 Tunnel 和私有插件；GitHub 发布项目源码不等于发布 ChatGPT 公共插件。P0 失败时报告阻塞，不擅自扩展到公网 HTTPS/OAuth。

P0 先验证文本 echo 与原任务澄清闭环；本机文件、shell 和应用操作能力单独验收，不作为纯文本探针前置。公开方案来源见[成熟方案核验](成熟方案核验.md)。

## 最小架构

技术基线：TypeScript、Node.js 24、Fastify、SQLite WAL、官方 MCP SDK `@modelcontextprotocol/server@2.3.1` / `@modelcontextprotocol/node@2.1.1`。

数据流：Codex → 本地控制入口 → 持久任务队列与 event outbox → 签名 webhook 提示 Dot → Dot 通过 Tunnel 调用任务工具 → 结果入库 → Codex 查询与 ACK。

- 控制入口：`/control/:op`，使用独立 caller Bearer token；CLI、Codex 接入共用业务操作。
- Dot 入口：`/mcp/dot`，仅监听环回地址；Tunnel 注入 `X-Codex-Dots-Worker-Token`，服务校验独立 worker token。
- `run` 使用随机环回端口，把实际 endpoint 写入 `config.json`；重启后的 Tunnel 配置必须与该 endpoint 对齐。
- 任务入库与 event outbox 原子提交；Events 仅提示，任务数据库是事实来源。订阅、回调 secret、发送重试和任务状态跨重启保存。
- 平台 runtime key、worker key、caller key 分开；平台 key 只供 Tunnel 使用。未公开的原生 Dot 身份不伪造，绑定通过用户在目标 Dot 订阅及可见闭环确认。

## 协作与可靠性契约

计划中的任务状态固定为：`queued`、`running`、`waiting_input`、`cancel_requested`、`reconciliation_required`、`completed`、`failed`、`cancelled`、`expired`。

- 每次补充或更正增加 input revision；领取产生 attempt 和租约，检查点返回最新输入及取消请求。旧租约不能提交新结果，完成须明确实际采用的输入 revision。
- 澄清持久化问题与 request ID；用户回答针对该问题更新输入，重新触发领取。处理中更正由 Dot 在检查点协作采用，不承诺即时修改正在执行的原生任务。
- 已完成任务的追问创建关联 followup，并携带相关上下文；逻辑关联不等于原生 Dot thread 接续。
- 未领取任务可以直接取消；运行中先标 `cancel_requested`，收到执行者停止回执才标 `cancelled`。桥接不能强制终止 Dot、委派任务或已经发生的外部动作。
- 失租默认转 `reconciliation_required`，避免自动重派造成重复外部动作；只有明确可重复任务才自动重试，最多 3 次。租约隔离不提供外部动作 exactly-once 保证。
- 结果已入库、Codex 已读取、用户或调用方 ACK 分开记录；webhook 2xx 只证明收到提示。终态和 ACK 不可混同。
- 订阅默认 24 小时，按服务器授予的 `refreshBefore` 自然续订；断线恢复重新读取队列，不能以 `cursor:null` 声称 Events 已重放历史。

Codex 当前回合可有界等待。回合结束后，首版靠用户在原对话主动查询/回答；App 关闭期间结果保留，重开后再取回。不使用本机私有 IPC，也不承诺自动恢复原 Codex 对话。可选原生自动化须在后续单独验证并获用户授权。

已确认的正式版本默认值与行为（未实现项按 P1/P2/P3 推进）：

- `dots_wait` 单次最多 20 秒，当前回合累计默认 5 分钟；用户可延长，到限仅返回状态，不取消、不重新派单。
- 桌面原对话回访默认每 15 分钟一次、最长 24 小时，只报告新问题或终态；用户通过官方功能开启，终态停止。CLI 不承诺桌面调度管理能力。
- 任务默认期限 24 小时；排队/等待输入可过期，运行中超期转待核对。初始租约 30 分钟，检查点续租。
- 保留入队、通知收件、领取、结果入库、Codex 取回 ACK、用户认可六层证据。结果正文支持文本、结构化数据与外部链接；不提供文件托管。
- Codex 端完整工具：`dots_submit`、`dots_list`、`dots_get`、`dots_wait`、`dots_message`、`dots_followup`、`dots_cancel`、`dots_status`、`dots_ack_result`。
- Dot 端完整工具：`list_tasks`、`get_task`、`claim_task`、`checkpoint_task`、`request_input`、`complete_task`、`fail_task`、`ack_cancel`，以及 Events 三方法。
- 生产维护 CLI：`setup`、`run`、`status`、`doctor`、`tasks`、`resolve`、`backup`、`restore`、`uninstall`；P0 临时命令不代表该体验已经交付。
- 安装检查本机冲突与项目所有权，保留无关 MCP、Skill、审批设置；一次账号绑定后无需手写配置。发布包私有 Node 24，不修改全局运行环境。
- 配置和密钥在用户数据目录；后台隐藏、可选登录自启；备份数据库及恢复所需密钥并保护权限；卸载只移除本项目注册项，默认保留数据。
- 平台登录和原生审批回到相应官方入口，业务澄清答案不构成平台授权。账号不可用时不得切换到未公开接口。

## 阶段及闸门

| 阶段 | 交付与完成条件 |
| --- | --- |
| P0 官方真实闭环 | 本地探针、官方 Tunnel、插件 Events discovery、目标 Dot 订阅、签名 challenge、任务领取、正文入库及一次澄清再完成；详见 [P0官方接入](P0官方接入.md)。 |
| P1 任务协作 | P0 通过后实现持久任务、输入 revision、租约/检查点、澄清、关联 followup、协作取消、结果查询及 ACK；代表性协作链路通过。 |
| P2 Windows Codex 接入 | P0 通过后提供 Windows x64 Codex 桌面版及本机 CLI 的安装向导/Skill、状态诊断、有界等待、可选原对话回访引导；原对话取回/人工接续边界有真实使用证据。 |
| P3 Windows 发布准备 | P0 通过后提供 Windows 发布包、私有 Node.js 24、备份恢复、安装/运行/故障文档、CI、MIT 归属及依赖许可核对；恢复与认证隔离实测，模拟与真实验证分列。 |
| P4 首版真实验收 | 关键协作、桌面/CLI原生调用和受控恢复完成；短时功能样本与自然续订/长期稳定性分开判定。 |

**P0 未通过前，P1–P4 均不得启动。** P0 可创建满足探针所需的最小存储、协议与 CLI，不因此宣布生产状态机、安装包或通用任务 Skill 已完成。

正式验收必须包含：桌面和 CLI 各一次完整协作、十个预定义无副作用任务、真实澄清/补充/追问/取消、关闭后找回原任务、服务与 Tunnel 中断后的恢复或待核对、实际观察窗口内核对零静默丢单与零未经允许的有副作用重派。自然续订如未发生则保留未验证；原对话回访仅在用户明确启用时验收，按明确启用的范围执行。

最终仓库交付包括中英文 README、快速开始、产品/架构/状态/工具契约、Codex Skill、Dot 指令、Windows 包、构建测试命令、诊断升级/备份恢复/卸载说明、真实证据与兼容矩阵、已知限制、MIT/第三方说明、贡献/Issue/PR 模板与变更日志。个人身份、运行状态和真实业务资料不得进入公开源码。

## 当前实施入口与状态

生产入口为 src/main.ts；当前源码候选为0.2.0-alpha.4。P0与后续真实文本协作已有证据，完整状态、九个caller/八个worker、Windows安装维护与Skill已实现；短时验证不代表长期稳定性。

生产入口为 `src/main.ts`：`setup`、`run`、`status`、`doctor`、`tasks`、`resolve`、`backup`、`restore`、`uninstall`；`stdio` 供 Codex 管理。默认数据在 `%LOCALAPPDATA%\CodexDotsBridge\data`。项目命令经 `scripts/dev.ps1 bridge -- <命令>` 执行；发布包使用私有 Node 和 `dist/main.js`。实际参数以 `--help` 为准。

旧 `src/cli.ts`、`scripts/dev.ps1 probe`、`queue=p0` 继续保留固定合成探针；新版使用 `queue=tasks` 和独立数据库，不把历史结果迁移成新生产任务。每位部署者必须完成自己的官方账号与连接配置。新版真实验收见 [P1–P4记录](P1-P4验收记录.md)，不得用本地模拟、Tunnel ready、事件收件代替真实任务完成。

## 验证与交接

阶段记录应说明已实现、模拟验证、真实运行、结果交付和用户验收分别成立到哪一步。P1–P4 依次验收推进；P1 包含断线/重启、失租与重复动作边界、认证隔离、签名与 SSRF 防护的实现与匹配检查，P4按当前短时验收窗口确认实际覆盖；自然续订与长期稳定性分别保留观察边界。实质性代码交付前由主代理安排专门代码审查，指定 `gpt-6.1-sol / high`，如实际机制或运行模型不可核实则如实说明。审查、CI或短期试跑不能冒充真实P0、跨日续订或长期稳定性证据。

后续接续先读本文、[P0官方接入](P0官方接入.md)、CLI help 及 evidence。出现关键阻塞先保留数据和证据，报告最小缺口；不切换部署路线或扩大产品范围。
